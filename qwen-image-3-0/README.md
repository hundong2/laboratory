원문은 JavaScript로 렌더링되는 페이지라 일반 HTML 추출에서는 본문이 보이지 않았지만, 실제 렌더링된 영문 본문을 확인했다. 이 자료는 원문의 제품 소개를 한국어 학습 문서로 재구성하고, 공식 API 문서에서 확인되는 호출 규격과 현재 제공 상태를 보완한다.

중요한 구분은 다음과 같다.

- **공식 발표에서 주장한 능력**: 최대 4.5K-token 입력, 10px급 작은 글자, 12개 언어, 100개 이상의 스타일, 복잡한 레이아웃과 이미지 편집
- **API 문서로 확인되는 규격**: `qwen-image-3.0-pro`, T2I와 I2I, 1~3장 참조 이미지, 512×512~2048×2048 출력 범위, 초대 테스트
- **공개되지 않은 정보**: 발표문에는 모델 구조, 파라미터 수, 학습 데이터, 독립 재현 가능한 비교 점수가 없다.

따라서 예시 이미지의 인상과 운영 환경의 실제 품질을 동일시하지 않고, 별도의 평가 데이터셋으로 검증해야 한다.

## 한눈에 보기

Qwen-Image-3.0은 단순히 보기 좋은 한 장의 그림보다 **정보 밀도가 높은 실무 시각물**을 겨냥한 이미지 생성·편집 모델이다. 발표문은 세 가지 축으로 설명한다.

| 축 | 의미 | 대표 작업 |
|---|---|---|
| Rich Content | 한 화면에 많은 요소를 논리적으로 배치 | 신문, 시험지, 3×3 인포그래픽, 스토리보드 |
| Authentic Details | 작은 글자와 미세 질감을 정밀하게 표현 | 수식, 논문 페이지, 피부·머리카락, 손글씨 주석 |
| Deep Knowledge | 언어·스타일·UI·세계 지식을 시각화 | 다국어 포스터, 웹·게임 UI, 교육 인포그래픽 |

실무에서는 “한 번에 긴 프롬프트를 넣는다”보다 다음 순서가 중요하다.

1. 전달 목적과 독자를 먼저 정한다.
2. 캔버스를 구역으로 나누고 공간 관계를 명시한다.
3. 화면에 실제로 보여야 하는 문자열을 따옴표로 고정한다.
4. 스타일, 카메라, 질감보다 정보 계층과 읽기 순서를 먼저 쓴다.
5. 결과물을 OCR, 레이아웃, 사실성, 편집 보존성으로 따로 평가한다.

## 기초 개념

### Text-to-Image와 Image-to-Image

- **T2I(Text-to-Image)**: 텍스트 프롬프트만으로 새 이미지를 생성한다.
- **I2I(Image-to-Image)**: 한 장 이상의 참조 이미지와 편집 지시를 함께 입력한다.
- **Reference image**: 유지할 인물, 사물, 구도 또는 스타일을 제공하는 입력 이미지다.
- **Prompt extension**: 짧은 사용자 지시를 모델 또는 별도 구성 요소가 더 상세한 프롬프트로 확장하는 기능이다.

Qwen-Image-3.0 API 문서는 T2I와 I2I를 하나의 메시지 구조로 다룬다. T2I는 `content`에 텍스트 하나를 넣고, I2I는 1~3개의 이미지와 텍스트 하나를 순서대로 넣는다.

### 정보 밀도와 시각 계층

정보가 많다고 좋은 인포그래픽이 되는 것은 아니다. 다음 네 수준을 분리해야 한다.

1. **콘텐츠 완전성**: 요청한 항목이 빠지지 않았는가?
2. **텍스트 정확성**: 철자, 숫자, 수식이 정확한가?
3. **공간 정확성**: 각 항목이 지정한 영역에 있는가?
4. **시각 계층**: 제목, 본문, 주석의 중요도가 한눈에 구분되는가?

긴 프롬프트는 콘텐츠 완전성에 유리할 수 있지만 서로 충돌하는 제약도 늘린다. 섹션별 책임을 분리하고, 같은 속성을 여러 문장으로 반복하지 않는 편이 좋다.

### 작은 글자 렌더링

발표문은 10px급 텍스트를 강조하지만, 이 숫자는 모든 해상도와 글꼴에서 항상 정확하다는 보증이 아니다. 실제 가독성은 다음 요소에 따라 달라진다.

- 최종 출력 해상도와 리사이즈 비율
- 문자 수, 언어, 글꼴과 자간
- 배경 대비와 압축
- 한 이미지에 들어가는 전체 정보량
- 후처리 과정의 축소·샤프닝

“10px 지원”은 테스트 가설로 다루고, 목표 배포 크기에서 OCR 정확도와 사람 판독률을 측정해야 한다.

### 세계 지식과 검색 연결

발표문은 날씨처럼 최신 정보를 활용하는 예를 보여 준다. 그러나 모델 내부 지식과 Qwen 서비스가 연결한 검색 도구는 다른 계층이다.

- **모델 지식**은 학습 시점과 데이터에 제한된다.
- **검색 결과**는 최신일 수 있지만 출처 오류와 해석 오류가 생길 수 있다.
- **이미지 렌더링** 단계에서 정확한 사실도 잘못된 숫자나 문자열로 변형될 수 있다.

최신 정보가 들어간 시각물은 검색 출처를 기록하고, 렌더링된 텍스트를 다시 검수해야 한다.

## 핵심 요약

### 1. Rich Content

원문은 3.7K-token 프롬프트로 3×3 격자 전체를 한 번에 만든 예를 제시한다. 각 칸은 터널 안전 만화, 공간기하, 문학 분석, 포물선 운동, 기생충학, 흉통 의학 도식, Sylow 정리, 은행 내부통제, DNA 구조 비교처럼 서로 다른 주제를 담는다.

이 능력은 두 방향으로 구분할 수 있다.

- **수평 확장**: 여러 개념을 같은 캔버스에 병렬 배치
- **수직 확장**: 화면 안의 화면처럼 논리적으로 중첩된 구조 표현

원문의 중첩 예시는 VS Code → Qwen Chat → WeChat → 핸드드립 커피 포스터의 순서다.

### 2. Authentic Details

원문이 강조하는 대상은 다음과 같다.

- 고래상어 인포그래픽의 작은 설명
- 대수기하학 논문의 LaTeX 수식과 위·아래 첨자
- 실제 종이 질감을 가진 신문
- 교과서 위의 붉은 손글씨 주석
- 인물의 피부, 모공과 머리카락
- 손상된 전통 회화의 화풍 보존 복원

텍스트 렌더링과 사진적 질감은 서로 다른 평가 축이다. 한 축의 성능이 좋다고 다른 축도 자동으로 좋다고 볼 수 없다.

### 3. Deep Knowledge

발표문은 12개 언어, 다양한 글꼴, 100개 이상의 예술 스타일, 웹·게임·라이브 방송 UI 표현을 언급한다. 일본어·한국어·스페인어 예시와 곤충 사진을 학술 인포그래픽으로 바꾸는 편집 사례도 제시한다.

다국어 지원은 언어별 동일 품질을 뜻하지 않는다. 한국어는 다음을 별도로 시험해야 한다.

- 받침과 복합 모음
- 줄바꿈 시 조사 분리
- 숫자·영문·한글 혼합 문장
- 작은 크기의 고딕·명조 계열
- 표와 그래프 안의 짧은 레이블

## 상세 정리

### 발표가 보여 주는 제품 방향

Qwen-Image 계열의 메시지는 “정확성”에서 “다양성·완전성·미감·사실성”을 거쳐, 3.0에서는 **실제로 쓸 수 있는 결과물**로 이동한다. 목표 분야는 디자인, 콘텐츠 제작, 교육, 전자상거래이며, 특히 다음 산출물이 강조된다.

- 신문·문서형 PDF 소재
- 짧은 드라마의 스토리보드
- 복잡한 UI 목업
- 교육용 슬라이드와 시험지
- 편집 가능한 마케팅 시안

### 공식 API 제공 상태

2026-07-24 확인 기준 공식 Alibaba Cloud 문서는 다음을 명시한다.

| 항목 | 규격 |
|---|---|
| 모델 ID | `qwen-image-3.0-pro` |
| 제공 상태 | 초대 테스트, 사전 사용 신청 필요 |
| 작업 | T2I, I2I/이미지 편집 |
| 참조 이미지 | I2I에서 1~3장 |
| 출력 크기 | 512×512~2048×2048 범위 |
| 출력 형식 | PNG |
| 생성 수 | 요청당 1~6장 |
| 주요 옵션 | `prompt_extend`, `size`, `negative_prompt`, `seed`, `watermark` |
| 지역 | 중국 베이징, 싱가포르 |

지역별 API key와 endpoint는 서로 호환되지 않는다. 반환된 이미지 URL은 문서상 24시간만 유효하므로 운영 코드에서는 즉시 사내 저장소로 복사하고, 원본 요청·seed·모델 ID와 함께 추적해야 한다.

### 구조화 프롬프트 패턴

복잡한 작업에는 다음 순서가 유용하다.

```text
[목표]
한국어 독자를 위한 A4 세로형 교육 인포그래픽

[캔버스와 구획]
상단 20%: 제목과 한 문장 요약
중앙 60%: 3단계 흐름도
하단 20%: 주의사항과 출처

[정확히 표시할 문자열]
"확산 과정", "노이즈 예측", "반복 복원"

[시각 관계]
왼쪽에서 오른쪽으로 화살표, 단계 번호 1→2→3

[스타일]
높은 명암 대비, 흰 배경, 남색 제목, 최소한의 장식

[금지]
가짜 로고, 읽을 수 없는 장식 문자, 출처 없는 수치 금지
```

### 긴 프롬프트의 함정

- 내용이 많아질수록 일부 조건이 누락될 수 있다.
- 서로 다른 섹션에서 색·위치 지시가 충돌할 수 있다.
- 정확한 텍스트를 설명 문장 속에 묻으면 모델이 바꿔 쓸 수 있다.
- 4.5K-token 한도는 목표치가 아니라 상한이다.
- 제품의 prompt extension이 사용자의 고정 문자열까지 바꿀 수 있으므로 A/B 검증이 필요하다.

### 이미지 편집 프롬프트

편집에서는 “바꿀 것”과 “보존할 것”을 분리한다.

```text
[보존]
인물의 얼굴 특징, 자세, 카메라 각도, 배경의 원근

[변경]
상의만 짙은 남색 재킷으로 교체

[추가]
왼쪽 가슴에 작은 이름표 "연구팀"

[금지]
얼굴형, 머리 길이, 손가락 수, 배경 인물 변경 금지
```

참조 이미지가 여러 장이면 “첫 번째 이미지의 인물”, “두 번째 이미지의 의상”처럼 배열 순서와 역할을 명시한다.

## 실무 평가 체크리스트

### 텍스트

- 모든 고정 문자열이 정확한가?
- 한글 자모가 깨지지 않았는가?
- 숫자, 단위, 수식과 날짜가 원문과 같은가?
- 목표 배포 크기에서 사람이 읽을 수 있는가?
- OCR 결과와 정답 문자열의 편집 거리를 기록했는가?

### 레이아웃

- 요구한 구획 수와 순서가 맞는가?
- 패널끼리 내용이 섞이지 않았는가?
- 중첩 UI의 부모·자식 관계가 맞는가?
- 중요 요소가 잘리거나 여백 밖으로 나가지 않았는가?

### 사실성과 지식

- 최신 정보에 출처와 시점이 있는가?
- 모델이 임의의 통계·로고·기관명을 만들지 않았는가?
- 의료·법률·금융 시각물은 전문가 검수를 받았는가?

### 편집

- 변경 대상만 바뀌었는가?
- 인물 정체성, 배경, 카메라가 보존됐는가?
- 반복 편집에서 품질이 누적 열화되지 않는가?

### 운영

- 모델 ID, prompt, seed, 옵션을 기록했는가?
- 반환 URL 만료 전에 결과를 저장했는가?
- 참조 이미지의 저작권과 개인정보 처리가 적절한가?
- 워터마크와 AI 생성물 표시 정책을 확인했는가?

## 공개 정보의 한계

2026-07-24 기준 공식 발표문에는 다음 자료가 포함되지 않는다.

- 3.0의 모델 구조와 파라미터 수
- 학습·후처리 데이터 구성
- 안전성 평가 방법과 실패율
- 비교 모델을 포함한 재현 가능한 benchmark 표
- 공개 weight 또는 3.0 전용 model card 링크

공식 Qwen Hugging Face collection에서 확인되는 공개 weight는 이전 세대 Qwen-Image와 2512·Edit 계열이다. 이는 “3.0이 공개되지 않을 것”이라는 뜻이 아니라, 확인 시점에 발표문만으로 로컬 실행법을 확정할 수 없다는 뜻이다.

## 용어 정리

| 용어 | 설명 |
|---|---|
| T2I | 텍스트로 이미지를 생성하는 작업 |
| I2I | 참조 이미지를 기반으로 새 이미지나 편집 결과를 생성하는 작업 |
| Prompt adherence | 프롬프트의 대상·속성·관계를 얼마나 충실히 지키는지 |
| Typography rendering | 글자 모양, 철자, 배치와 크기를 이미지 안에 표현하는 능력 |
| Spatial control | 객체와 패널의 위치·크기·포함 관계를 제어하는 능력 |
| Semantic juxtaposition | 서로 다른 개념을 같은 화면에 병렬로 배치하는 능력 |
| Logical nesting | 화면 안의 화면처럼 계층 구조를 표현하는 능력 |
| Prompt extension | 짧은 프롬프트를 자동으로 상세화하는 기능 |
| Seed | 확률적 생성의 초기값. 같은 seed도 서비스 변경에 따라 동일 결과를 보장하지 않는다. |
| OCR | 이미지 속 문자를 기계가 읽어 문자열로 바꾸는 기술 |

## 실습 학습 가이드

모든 노트북은 Python 표준 라이브러리만 사용하며 API 호출이나 비용을 발생시키지 않는다.

1. [01_foundations.ipynb](01_foundations.ipynb)
   - 복잡한 이미지 프롬프트를 목표·레이아웃·고정 문자열·스타일·금지 조건으로 분해한다.
   - 간단한 길이 추정과 충돌 검사를 실습한다.
2. [02_practice.ipynb](02_practice.ipynb)
   - 공식 메시지 형식에 맞는 T2I·I2I payload를 만든다.
   - key나 네트워크 없이 dry-run validator로 입력 오류를 찾는다.
3. [03_advanced.ipynb](03_advanced.ipynb)
   - 텍스트 정확성, 레이아웃, 사실성, 세부 표현, 보존성을 분리 평가한다.
   - 가중 점수와 실패 gate를 이용해 후보 이미지를 비교한다.
