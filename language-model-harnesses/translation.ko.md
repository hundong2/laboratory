## 제목과 중심 주장

원문 제목은 "Language model harnesses are compositional generalizers"이다. 한국어로 옮기면 "언어 모델 하네스는 조합적 일반화 장치다" 정도가 된다.

핵심 주장은 다음과 같다. 현대의 post-training은 점점 더 많은 환경, 더 긴 작업, 더 큰 문맥을 모으는 방향으로 발전해 왔다. 하지만 Transformer가 처음 보는 문제를 익숙한 부분 문제의 조합으로 푸는 능력, 즉 조합적 일반화에는 여전히 약점이 있다. 저자들은 이 일반화 능력의 상당 부분이 모델 자체가 아니라 모델을 둘러싼 하네스에 들어갈 수 있다고 주장한다.

## 더 나은 스케일링에는 조합적 일반화가 필요하다

AI의 어려운 문제는 대체로 일반화 문제로 돌아온다. 특정 애플리케이션을 겨냥한 환경과 데이터를 계속 추가하는 방식은 효과가 있지만, 모든 새로운 도메인마다 별도의 데이터와 훈련을 요구한다.

저자들은 인간이 중요하게 여기는 많은 과제가 자연스럽게 더 작은 하위 과제로 분해될 수 있다고 본다. 긴 코드베이스 수정, 긴 문서 분석, 대규모 검색과 집계 작업은 겉으로는 매우 다르지만, 안쪽에는 "찾기, 비교하기, 부분 결과 저장하기, 합치기" 같은 반복 가능한 구조가 있다.

따라서 시스템이 배워야 할 것은 표면 텍스트 전체가 아니라 이런 분해 구조다. 이것이 조합적 일반화의 핵심이다.

## 조합적 일반화 능력은 하네스에 들어갈 수 있다

하네스는 외부 세계와 신경망 사이에 있는 프로그램이다. 환경 상태 `s`를 받아 언어 모델이 볼 하나 이상의 관찰 `o`로 바꾸고, 그 결과를 이용해 다음 행동 `a`를 결정한다.

일반적인 에이전트 구현은 상태, 도구 출력, 이전 행동, 추론 흔적을 하나의 길어지는 프롬프트에 계속 붙인다. 정보는 많아지지만 루트 모델이 보는 입력은 점점 훈련 분포에서 멀어진다. 저자들은 이 문제가 context rot으로 나타난다고 본다.

좋은 하네스는 전체 상태가 분포 밖이어도 각 모델 호출이 지역적으로는 분포 안에 있도록 만든다. 즉, 한 번의 모델 호출이 처리할 관찰은 짧고 익숙한 형태여야 한다. 하네스는 복잡한 문제를 여러 개의 단순한 호출로 바꾸는 귀납적 편향을 제공한다.

## RLM은 서로 다른 과제를 같은 구조로 보게 만든다

Recursive Language Model(RLM)은 이런 하네스 설계를 구현한 예다. RLM은 루트 모델이 전체 입력을 직접 읽는 대신, 긴 입력과 중간 결과를 변수나 실행 상태로 오프로딩하고 필요한 부분만 서브 호출로 넘긴다.

저자들이 강조하는 두 장치는 다음과 같다.

| 장치 | 역할 |
| --- | --- |
| Context offloading | 입력별 세부 문맥을 루트 프롬프트에 붙이지 않고 변수처럼 참조한다. |
| Programmatic sub-agent calling | 서브 에이전트와 도구를 함수처럼 호출하고 결과를 REPL 상태에 저장한다. |

이렇게 하면 서로 다른 도메인의 과제라도 루트 모델이 보는 궤적은 거의 같다. 루트 모델은 "데이터를 청크로 나누고, 각 청크를 서브 호출에 보내고, 결과를 집계한다"는 구조를 학습한다. 도메인별 텍스트는 서브 호출 내부에서만 처리된다.

## 길이 일반화 실험

원문은 짧은 과제에서만 학습한 RLM이 훨씬 긴 평가 과제에 전이되는지 실험한다. 사용한 모델은 Qwen3-30B-A3B-Instruct-2507이며, RLM, 분해 힌트를 준 RLM, YaRN을 적용한 일반 Transformer를 비교한다.

실험 환경은 다음과 같이 길이가 달라지는 작업들이다.

| 환경 | 평가 아이디어 |
| --- | --- |
| MRCRv2 | 긴 대화 말뭉치에서 특정 needle 문장을 찾는다. |
| GraphWalks | 그래프에서 조건을 만족하는 노드를 추출한다. |
| LongBenchPro | QA, 코드, 추론형 긴 문맥 문제를 푼다. |
| OOLONG | 데이터셋에 대한 집계형 질문에 답한다. |
| OOLONG-Pairs | 조건을 만족하는 쌍을 찾는다. |
| Ada-LEval | 많은 후보 답변 중 질문에 가장 적합한 답을 고른다. |

보고된 핵심 결과는 RLM이 짧은 훈련 과제에서 배운 전략을 8-32배 긴 평가 과제로 전이했다는 것이다. 일반 Transformer는 훈련 보상이 올라가도 긴 평가 과제에서는 개선이 제한적인 경우가 많았다.

저자들은 이 차이를 루트 모델의 관찰 구조에서 찾는다. RLM은 긴 과제에서도 루트 모델이 보는 구조가 짧은 과제와 거의 같고, 차이는 서브 호출의 횟수와 내용에 주로 있다. 반대로 일반 Transformer는 긴 문맥 전체가 프롬프트에 들어가므로 루트 모델 자체가 긴 분포 밖 입력을 직접 처리해야 한다.

## 도메인 또는 전략 일반화 실험

다음 실험은 같은 길이 문제가 아니라 서로 다른 도메인 사이의 전이를 본다. 예를 들어 TREC 질문 집계에서 spam/ham 질문 집계로, 글쓰기 유사성 검색에서 수학 문제 검색으로, Twitter stance 검색에서 Wildchat 오류 검색으로 옮긴다.

표면 단어와 도메인은 다르지만 필요한 분해 전략은 비슷하다. 원문은 이런 경우 RLM이 일반 Transformer보다 평가 성능을 더 잘 끌어올렸다고 보고한다. 이는 RLM이 도메인별 텍스트보다 분해 전략을 학습했기 때문이라는 해석으로 이어진다.

## 궤적 유사도와 등가 클래스

저자들은 RLM 하네스가 과제 궤적 위에 등가 관계를 만든다고 설명한다. 두 과제가 겉으로 다르더라도 하네스를 통과한 루트 궤적이 비슷하면, 루트 모델은 두 과제를 같은 문제 유형으로 볼 수 있다.

부록에서는 평가 궤적과 훈련 궤적의 거리를 재기 위한 대략적 지표를 제시한다.

| 지표 | 의미 |
| --- | --- |
| 정규화 Levenshtein 거리 | 토큰 편집 거리 기반 유사도 |
| 3-gram containment | 평가 궤적의 3-gram이 훈련 궤적에 얼마나 포함되는지 |
| 3-gram Jaccard | 두 궤적의 3-gram 집합 유사도 |
| Weighted Jaccard | 토큰 또는 n-gram 빈도까지 반영한 유사도 |
| Length ratio | 두 궤적 길이가 얼마나 비슷한지 |

이 지표들은 완전한 의미론적 증명은 아니지만, RLM 루트 궤적이 일반 Transformer의 긴 누적 문맥보다 훈련 중 본 궤적에 더 가깝다는 정량적 힌트를 제공한다.

## 비용과 한계

RLM 학습은 단순 Transformer 학습보다 비싸다. 원문은 RLM 학습이 여러 단계와 서브 호출 대기 때문에 비슷한 크기 작업에서 약 1.5-3배 더 오래 걸릴 수 있다고 설명한다.

또한 RLM이 항상 좋은 분해 전략을 배우는 것도 아니다. 짧은 과제에서는 전체 문제를 하나의 서브 호출에 넘겨도 성공할 수 있다. 이 경우 긴 과제에서는 서브 호출 자체가 너무 커져 다시 분포 밖 문제가 된다. 따라서 좋은 하네스는 "오프로딩"뿐 아니라 "적절한 분해"를 함께 유도해야 한다.

## 스케일링 관점의 결론

저자들은 데이터 스케일링이 여전히 중요하다고 본다. 다만 데이터를 먹이는 구조, 즉 하네스와 그 귀납적 편향이 스케일링의 효율을 결정한다고 주장한다.

핵심 실천 원리는 단순하다. 복잡한 문제를 지역적으로 익숙한 관찰들의 시퀀스로 바꾸어라. 하네스가 이 일을 잘할수록 모델은 새 도메인과 더 긴 작업을 기존에 배운 구조의 조합으로 다룰 수 있다.
