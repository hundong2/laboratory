## 한눈에 보기

장기 과제의 LLM 에이전트는 대화 문맥만으로 현재 세계 상태, 끝낸 일, 실패 경험을 모두 유지하기 어렵다. 보통 메모리·상태 추적기·도구를 덧붙이지만, **언제 읽고 언제 기록할지**는 프롬프트와 수작업 규칙에 남는다.

EvoHarness-RL은 외부 작업 공간을 다음 세 상태로 나눈다.

| 상태 | 질문 | 역할 |
| --- | --- | --- |
| Belief(B) | 지금 무엇이 사실인가? | 관찰에서 추론한 환경 상태와 과제 관련 사실 |
| Progress(P) | 어디까지 했는가? | 하위 목표, 완료·대기·차단 상태, 시도 이력 |
| Experience(E) | 이전에 무엇을 배웠는가? | 재사용 기술, 실패 유형, 탐색 사전지식 |

정책 모델은 환경 행동뿐 아니라 `track`, `commit`, `recall`, `note`라는 하네스 행동도 선택한다. SFT로 이 행동 문법을 익힌 뒤 비용 인식 GRPO로 호출 시점까지 학습한다. 저자들은 ALFWorld의 본 140개 과제에서 Qwen3-8B 기반 모델이 평균 성공률 96.9%를 기록했다고 보고한다.

## 기초 개념

### 에이전트 하네스란

하네스(harness)는 모델 바깥에서 실행을 지탱하는 프롬프트, 도구, 검색, 메모리, 상태 추적, 검증, 제어 흐름의 묶음이다. 모델의 파라미터가 장기 기억을 매 실행마다 바꾸는 대신, 하네스가 명시적인 외부 상태를 보관한다.

### 왜 메모리만 늘리면 부족한가

큰 메모리도 매 단계 전부 읽으면 토큰·지연 비용이 커지고, 오래되거나 관련 없는 정보가 판단을 방해한다. 쓰기를 무제한 허용하면 중복·오류가 축적된다. 핵심 문제는 저장 공간의 크기보다 **상태를 어떻게 만들고, 어떤 순간에 접근할지**이다.

### SFT와 GRPO의 역할

- 지도 미세조정(SFT)은 성공한 교사 궤적을 보고 하네스 행동 형식과 유용한 기록 방식을 모방하게 한다.
- 그룹 상대 정책 최적화(GRPO)는 여러 후보 궤적의 상대 보상을 사용해 성공뿐 아니라 효율·호출 다양성·스팸·형식 오류까지 반영한다.

## 핵심 요약

1. **하네스 정책 학습**: 외부 상태를 수동 규칙으로만 다루지 않고 정책이 실행 중 구성·갱신하도록 만든다.
2. **BPE 상태 분해**: 사실, 실행 진행, 에피소드 간 경험을 분리해 서로 다른 수명과 갱신 규칙을 갖게 한다.
3. **두 단계 학습**: 성공 궤적 SFT로 안전한 출발점을 만든 후 비용 인식 GRPO로 선택적 접근을 학습한다.
4. **하네스 어닐링**: 학습 초반에는 외부 상태를 자주 사용하지만, 반복 패턴을 정책이 내재화하면서 후반에는 필요한 때만 호출한다.
5. **하네스 진화**: 경험 저장소가 무한히 커지는 대신 추가·수정·삭제·건너뛰기를 통해 압축된 과제 적응 상태로 바뀐다.

## 방법 상세

### 통합 외부 상태와 행동

시간 `t`의 정책 노출 상태는 `H_t = (B_t, P_t, E_t)`로 표현한다. 에이전트의 선택 공간에는 환경 행동과 아래 메타 행동이 함께 들어간다.

| 행동 | 접근 대상 | 의미 |
| --- | --- | --- |
| `track` | Belief 읽기 | 현재 과제에 필요한 환경 사실을 확인 |
| `commit` | Progress 쓰기 | 하위 목표와 실행 결과를 확정 |
| `recall` | Experience 읽기 | 재사용 가능한 기술·실패·탐색 지식 검색 |
| `note` | Experience 후보 쓰기 | 나중에 통합할 새 통찰 기록 |

하네스 행동도 상호작용 예산을 소비한다. 따라서 항상 호출하는 정책은 성공하더라도 비용 측면에서 불리하다.

### ALFWorld 어댑터

논문의 구현은 도메인 어댑터로 BPE를 ALFWorld에 연결한다. Belief는 규칙 기반 월드 상태 파서이며 최대 48개 항목, Progress는 최대 8개 하위 목표를 보관한다. Experience는 일반 기술·과제별 기술·흔한 실수·물체 위치 탐색 사전의 네 범주이며 범주당 최대 80개, 검색 `top-k=3`, 사용 빈도 기반 LFU 퇴출을 쓴다.

### 학습 파이프라인

1. Claude Opus 교사가 같은 BPE 인터페이스로 ALFWorld 훈련 게임을 수행한다.
2. 성공 궤적만 골라 Qwen3-8B에 다음 행동 SFT를 한다.
3. SFT 체크포인트에서 비용 인식 GRPO를 수행한다.
4. 에포크 경계에서 경험을 추가·수정·삭제·유지하며 통합한다.

500개 게임에서 성공한 87개 궤적이 1,153개의 다음 행동 쌍을 만들었고, 에피소드당 평균 길이는 26.5턴이었다.

### 보상 설계의 직관

보상은 엄격한 과제 성공을 중심으로 다음 항을 결합한다.

```text
R = 과제 성공 + 성공 시 효율 보너스 + 시간 의존 행동 다양성
    - 과도한 하네스 호출 - 잘못된 형식
```

효율 보너스는 실패를 짧게 끝내는 편법을 막기 위해 성공 시에만 적용한다. 다양성 항은 초반 탐색을 유도하지만 점차 약해진다. 이 설계가 호출 빈도가 감소하는 어닐링과 연결된다.

## 실험과 결과

### 설정

- 환경: ALFWorld/ALFRED 계열 텍스트 기반 체화 과제
- 과제군: Pick, Look, Clean, Heat, Cool, Pick2
- 정책 모델: Qwen3-8B
- 본 분할: 140개 과제, 에피소드 최대 70단계
- 미관측 분할: 학습 중 보지 않은 과제로 일반화 평가
- RL: GRPO, 그룹 8, 스텝당 프롬프트 16개·궤적 128개, 150 에포크
- 최적화: AdamW, 학습률 `1e-6`, KL 계수 `0.01`, gradient clipping `1.0`
- 문맥/응답 한도: 12,288/512 토큰
- 보고된 장비: NVIDIA H200 GPU 8장, vLLM tensor parallelism 4

### 주요 성공률

| 방법 | 본 분할 평균 | ReAct 대비 |
| --- | ---: | ---: |
| ReAct, Qwen3-8B | 47.9% | - |
| EvoHarness-Base | 56.4% | +8.5%p |
| EvoHarness-SFT | 68.6% | +20.7%p |
| EvoHarness-RL | **96.9%** | **+49.0%p** |

저자 보고값이며 이 저장소의 노트북으로 원 수치를 재현한 것은 아니다.

미관측 분할에서는 ReAct 50.0%, 추론 시점 BPE 77.6%, SFT 69.4%, EvoHarness-RL 86.6%였다. SFT가 단순 BPE보다 낮은 결과는 성공 교사의 특정 호출 패턴에 과적합될 가능성을 보여 주며, RL 단계의 선택적 조정이 일반화에 중요하다는 해석을 뒷받침한다.

### 구성요소 제거 실험

| 구성 | 평균 성공률 |
| --- | ---: |
| 전체 BPE | 56.4% |
| Belief 제거 | 55.0% |
| Progress 제거 | 50.7% |
| Experience 제거 | 48.6% |

이 추론 시점 실험에서는 Experience의 전체 영향이 가장 크고 Progress가 장기 하위 목표에 중요했다. Belief의 효과는 과제군에 따라 달라졌다. 이 결과는 학습 완료 모델의 인과적 분해와 같다고 단정할 수 없다.

## 재현과 실무 적용

### 소규모 재현 전략

공식 코드 링크를 확인하지 못했고 원 학습은 8×H200을 사용하므로, 제공 노트북은 다음 질문만 검증한다.

- B/P/E를 분리하면 상태 갱신과 디버깅이 쉬워지는가?
- 하네스 호출에 비용을 부여하면 선택적 정책이 항상 호출하는 정책보다 유리한가?
- 경험 통합과 호출 확률 감소가 저장소 크기·오류율을 어떻게 바꾸는가?

### 제품 적용 체크리스트

- 상태 항목에 출처, 관찰 시각, 신뢰도, 만료 시간을 붙인다.
- 사용자 입력을 경험 저장소에 바로 확정하지 말고 검증·격리한다.
- 도구 출력과 메모리는 스키마 검증 후 저장해 프롬프트 주입을 줄인다.
- `commit`과 `note`를 감사 로그로 남기고, 삭제·수정 이력을 추적한다.
- 성공률뿐 아니라 토큰, 지연, 호출 수, 오래된 기억 적중률을 함께 측정한다.
- 중요한 실행은 외부 상태가 손상되거나 검색에 실패해도 안전하게 중단되도록 설계한다.

## 한계와 비판적 읽기

- 보고된 본 실험 환경은 ALFWorld 하나다. 웹, 코드, 실제 로봇 같은 다른 장기 과제로 일반화되는지는 추가 검증이 필요하다.
- Belief 파서, Experience 범주, 보상 항은 사람이 도메인에 맞춰 설계했다. 완전히 자동으로 하네스를 발견한 것은 아니다.
- 교사 데이터와 경험 통합에 Claude Opus를 사용해 비용과 재현 의존성이 남는다.
- 본 분할 96.9%는 강한 결과지만 미관측 분할은 86.6%로 낮다. 본 분할만으로 일반화를 평가하면 과대 해석할 수 있다.
- 공개 코드가 확인되지 않아 구현 세부, 데이터 분할, 난수 시드까지 동일한 독립 재현은 어렵다.
- 외부 기억은 개인정보·비밀·악성 지시를 장기간 보존할 수 있다. 성능 개선과 별개로 보안·삭제 정책이 필수다.

## 용어 정리

| 용어 | 뜻 |
| --- | --- |
| Harness | 모델 외부에서 상태·도구·제어 흐름을 제공하는 실행 지원 계층 |
| BPE | Belief, Progress, Experience로 나눈 정책 노출 외부 상태 |
| Harness policy | 언제 외부 상태를 읽고 쓰고 통합할지 결정하는 정책 |
| SFT | 정답 행동이 있는 예제로 정책을 지도 미세조정하는 방식 |
| GRPO | 그룹 내 후보들의 상대 보상으로 정책을 최적화하는 방식 |
| Annealing | 학습이 진행되며 하네스 호출이 빈번한 사용에서 선택적 사용으로 감소하는 현상 |
| Consolidation | 중복·오류 경험을 합치거나 수정·삭제해 기억을 압축하는 과정 |
| LFU | 가장 적게 사용된 항목을 먼저 퇴출하는 캐시 정책 |

## 다음 학습 경로

1. 첫 노트북에서 `track/commit/recall/note`의 입력 스키마를 바꿔 본다.
2. 둘째 노트북의 호출 비용과 스팸 벌점을 바꾸고 정책 순위가 뒤집히는 지점을 찾는다.

5. 그 뒤 오프라인 궤적으로 SFT하고, 안전한 샌드박스에서만 쓰기 정책을 최적화한다.
