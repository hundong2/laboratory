## 한눈에 보기

Nexus는 시계열 예측을 단순한 숫자 외삽 문제가 아니라, 숫자 패턴과 사건 맥락을 함께 읽어야 하는 에이전트 추론 문제로 본다. 기존 시계열 파운데이션 모델은 계절성, 추세, 장기 의존성 같은 수치 패턴에는 강하지만 뉴스, 정책, 실적 발표 같은 비정형 맥락을 직접 이해하지 못한다. 반대로 LLM은 텍스트 맥락을 잘 읽지만 연속 수치 예측에는 불안정하다.

Nexus의 핵심 아이디어는 하나의 모델에 모든 일을 맡기지 않는 것이다. 먼저 과거 수치와 텍스트 사건을 구조화하고, 거시 에이전트가 큰 흐름을, 미시 에이전트가 단기 촉매를 따로 예측한다. 이후 종합 에이전트가 두 관점을 결합하고, 보정 에이전트가 과거 백테스트 오차에서 반복적으로 통하는 규칙만 남겨 최종 예측을 조정한다.

## 기초 개념

### 시계열 예측

시계열은 시간 순서가 있는 관측값의 나열이다. 예를 들어 주간 주가, 월별 매물 수, 일별 전력 사용량이 모두 시계열이다. 예측 문제에서는 과거 관측 구간 `X_1..X_tau`를 보고 미래 `T`개 시점의 값을 추정한다. 여기서 `T`를 예측 구간 또는 horizon이라고 부른다.

### TSFM과 LLM의 역할 차이

TSFM(Time Series Foundation Model)은 대규모 수치 시퀀스로 학습된 시계열 전용 모델이다. 수치 패턴에는 강하지만 현실 사건을 설명하는 텍스트를 직접 이해하는 데 한계가 있다.

LLM(Large Language Model)은 뉴스, 보고서, 이벤트 설명 같은 비정형 텍스트를 잘 처리한다. 하지만 연속적인 숫자 값을 정밀하게 자기회귀 예측하는 구조로 만들어진 모델은 아니므로, 숫자만으로 안정적인 시계열 예측을 하기는 어렵다.

### 멀티모달 예측

Nexus가 다루는 입력은 두 종류다.

- 수치 시계열: `x_t`
- 같은 시점의 텍스트 사건: `e_t`

현실의 많은 시계열은 둘을 함께 봐야 이해된다. 예를 들어 주가 하락이 단순한 계절 변동인지, 규제 발표나 실적 쇼크 때문인지는 텍스트 맥락 없이는 분리하기 어렵다.

### MAPE와 RMSE

MAPE는 실제값 대비 절대 오차의 비율을 평균낸 지표다. 서로 규모가 다른 시계열을 비교할 때 유용하지만 실제값이 0에 가까우면 불안정하다.

RMSE는 오차 제곱의 평균에 루트를 씌운 값이다. 큰 오차에 더 민감하므로 급격한 실패를 잘 드러낸다.

## 핵심 요약

- Nexus는 예측값뿐 아니라 예측 근거까지 함께 출력하는 프레임워크다.
- 문제를 컨텍스트화, 거시 예측, 미시 예측, 종합, 보정 단계로 나눈다.
- 컨텍스트화 단계는 긴 수치와 텍스트 입력을 시점별 원인-결과 타임라인으로 바꾼다.
- 거시 에이전트는 전체 예측 구간의 큰 추세와 국면을 본다.
- 미시 에이전트는 각 미래 시점의 단기 촉매와 국소 변동을 본다.
- 종합 에이전트는 거시와 미시 전망을 결합해 최종 수치와 자연어 근거를 만든다.
- 보정 에이전트는 순차 백테스트에서 반복적으로 나타나는 오류 패턴만 규칙으로 채택한다.
- PyTorchKR 정리에 따르면 Nexus는 Zillow 부동산 지표와 주식 데이터 평가에서 강한 CoT 프롬프트 및 TimesFM-2.5와 맞먹거나 일부 설정에서 앞서는 결과를 보였다.
- 단, 평가는 두 데이터셋 중심이며 단일 실행 평가라는 한계가 있다.

## 상세 정리

### 문제 정의

전통적인 시계열 예측은 보통 과거 숫자 `X_1..X_tau`만 보고 미래 숫자 `X_tau+1..X_tau+T`를 예측한다. Nexus는 여기에 같은 시점의 비정형 텍스트 `E_1..E_tau`를 함께 넣는다. 목표 출력도 단순 숫자가 아니라 다음 두 가지다.

- 미래 수치 예측값
- 예측을 이끈 사건, 추세, 촉매에 대한 자연어 근거

즉 Nexus가 근사하려는 함수는 "숫자와 사건 맥락을 입력받아 예측값과 설명을 함께 생성하는 함수"다.

### 1단계: 컨텍스트화

긴 원시 시계열과 긴 텍스트를 LLM에 그대로 넣으면 중요한 정보가 중간에서 묻히기 쉽다. Nexus는 먼저 과거 맥락 에이전트를 사용해 각 시점의 수치 변화와 사건 요인을 연결한 구조화된 타임라인을 만든다.

학습 관점에서 이 단계는 피처 엔지니어링과 비슷하다. 다만 사람이 직접 변수 목록을 설계하는 대신, 에이전트가 "이 시점의 값은 어떤 사건과 연결되는가"를 정리한다.

### 2단계: 이중 해상도 전망

Nexus는 미래를 한 가지 해상도로만 보지 않는다.

거시 추론 에이전트는 전체 예측 구간의 큰 궤적을 잡는다. 예를 들어 "시장 전체가 회복 국면에 들어간다", "재고가 계절적으로 줄어드는 기간이다" 같은 긴 호흡의 판단을 한다.

미시 추론 에이전트는 각 미래 시점의 단기 촉매를 본다. 예를 들어 "다음 주에는 실적 발표 반응이 남아 있다", "정책 뉴스의 영향은 2주 뒤 약해질 수 있다"처럼 짧은 구간의 변동을 다룬다.

두 에이전트를 분리하면 큰 추세와 짧은 이벤트를 한 프롬프트 안에서 서로 방해하지 않게 만들 수 있다.

### 3단계: 종합과 보정

종합 에이전트는 거시 예측과 미시 예측을 결합한다. 중요한 점은 단순 평균이 아니라, 어떤 관점을 왜 더 믿는지 설명까지 만든다는 것이다. 예측값이 틀리더라도 판단 구조를 검토할 수 있다는 점에서 운영 시스템에 유리하다.

보정 에이전트는 과거 데이터를 여러 순차 구간으로 나누어 백테스트한다. 각 구간에서 어떤 오류가 반복되는지 찾고, 여러 훈련 폴드에서 공통으로 나타나는 규칙만 남긴다. 이후 숨겨둔 검증 폴드에서 일정 수준 이상 성능이 좋아질 때만 이 규칙을 최종 예측에 적용한다.

이 방식의 목적은 단일 과거 구간에 과적합한 "그럴듯한 설명"을 막는 것이다.

### 실험 결과 해석

PyTorchKR 정리에 따르면 연구진은 LLM의 지식 컷오프 이후 기간에 해당하는 Zillow 부동산 지표와 주식 시장 데이터를 구성했다. 비교 대상은 전용 TSFM인 TimesFM-2.5와 강하게 튜닝된 CoT 프롬프트 기반 LLM 예측이었다.

게시글에 정리된 주요 결과는 다음과 같다.

- Gemini-3.1-Pro 기준 Zillow 멀티모달 예측에서 Nexus는 CoT 대비 평균 MAPE와 RMSE를 낮췄다.
- 주식 데이터에서는 평균 기준으로 소폭 앞섰지만 일부 구간에서는 CoT나 TSFM이 근소하게 앞선 경우도 있었다.
- 수치 전용 설정에서도 Nexus는 TimesFM-2.5와 맞먹거나 일부 평균 지표에서 앞섰다.
- 추론 품질 평가는 교차 심사 방식으로 진행되었고, 게시글은 Nexus의 근거 설명이 CoT보다 선호된 비율이 높았다고 정리한다.
- 컴포넌트 제거 실험에서는 거시, 미시, 보정 요소를 제거할 때 모두 성능이 악화되어 세 축이 모두 기여하는 것으로 나타났다.

이 결과는 "LLM이 시계열을 잘 맞힌다"는 단순 결론보다, "LLM의 숫자 추론과 텍스트 추론을 어떻게 조직하느냐가 성능을 좌우한다"는 설계 관점으로 읽는 편이 정확하다.

### 한계와 주의점

- 평가 데이터셋이 Zillow와 일부 주식 데이터에 제한된다.
- LLM 사전학습 데이터에 대한 간접 유출 가능성을 완전히 제거하기는 어렵다.
- 멀티 에이전트 호출은 비용이 크므로 반복 실행을 통한 분산 측정이 제한적이다.
- 예측 설명이 그럴듯하다고 해서 항상 인과적으로 맞다는 뜻은 아니다.
- 실제 운영에서는 데이터 수집, 이벤트 정규화, 검증 지표, 실패 시 롤백 기준이 별도로 필요하다.

## 용어 정리

| 용어 | 뜻 |
| --- | --- |
| TSFM | 대규모 시계열 데이터로 학습된 시계열 파운데이션 모델 |
| LLM | 텍스트 이해와 생성에 강한 대형 언어 모델 |
| Horizon | 미래 몇 시점까지 예측할지 나타내는 길이 |
| Contextualization | 원시 수치와 텍스트를 예측에 쓰기 쉬운 구조로 정리하는 단계 |
| Macro reasoning | 전체 구간의 큰 추세, 국면, 장기 흐름을 보는 추론 |
| Micro reasoning | 개별 시점의 단기 촉매와 국소 변동을 보는 추론 |
| Synthesis | 여러 예측 관점을 최종 예측과 근거로 결합하는 단계 |
| Calibration | 과거 오차를 분석해 예측 전략을 보정하는 과정 |
| Backtesting | 과거 어느 시점으로 돌아간 것처럼 예측하고 실제 결과와 비교하는 검증 방법 |
| MAPE | 실제값 대비 절대 오차 비율의 평균 |
| RMSE | 큰 오차에 민감한 제곱근 평균 제곱 오차 |
| Data leakage | 평가 시점에 알 수 없어야 하는 정보가 모델 입력이나 학습에 섞이는 문제 |

## 실습 학습 가이드

필요 패키지는 `requirements.txt`에 정리했다. 새 환경에서는 다음 명령으로 설치한다.

```bash
pip install -r nexus-agentic-time-series-forecasting/requirements.txt
```

- `01_foundations.ipynb`: 시계열, 예측 구간, 이벤트 효과, MAPE/RMSE를 작은 데이터로 익힌다.
- `02_practice.ipynb`: 컨텍스트 에이전트, 거시 에이전트, 미시 에이전트, 종합 에이전트를 함수로 구현해 Nexus의 축소판을 만든다.
- `03_advanced.ipynb`: 순차 백테스트와 검증 임계값을 사용해 보정 규칙을 채택하거나 폐기하는 과정을 실습한다.

각 노트북은 공식 모델 재현이 아니라 구조 이해용이다. LLM API를 호출하지 않고, 텍스트 이벤트를 규칙 기반 신호로 바꾸어 에이전트 구조를 눈으로 확인할 수 있게 했다.
