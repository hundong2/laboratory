## 한눈에 보기

Gazebo에서 심층강화학습(DRL)을 할 때 외부 메시지 전달과 비동기 시뮬레이션 진행이 정책의 행동과 관측 사이에 불규칙한 물리 스텝을 끼워 넣을 수 있다. 이 논문은 **행동 한 번 → 제어 간격만큼 물리 스텝 진행 → 상태 관측·보상 반환**을 동기식으로 묶는 GzDRL 프레임워크를 제안한다. 단일 환경뿐 아니라 여러 Gazebo 서버를 병렬 운용하고 일부 환경이 끝나는 즉시 배치를 돌려주도록 설계했다.

논문의 핵심 질문은 “물리 시뮬레이션을 정확한 시점에 제어하면서 학습 실험을 재현하고, 병렬 환경의 처리량까지 확보할 수 있는가?”이다. 답은 **저자들이 측정한 특정 상태 기반 UAV 과제와 하드웨어 조건에서 그렇다**는 것이다. 이미지 렌더링의 완전한 결정론이나 모든 환경·하드웨어에서의 최고 속도를 입증한 것은 아니다.

## 기초 개념

1. **강화학습의 전이:** 시각 \(t\)의 관측 \(o_t\)에서 정책이 행동 \(a_t\)을 고르고, 시뮬레이터가 다음 관측·보상·종료 여부를 반환한다. 같은 조건으로 비교하려면 행동과 물리 스텝의 대응이 중요하다.
2. **물리 스텝과 제어 주기:** 궤적 추적 정책 학습 설정에서는 물리 간격이 1 ms, 제어 주파수가 100 Hz다. 따라서 그 설정의 제어 행동 한 번 사이에 물리 스텝 \(K=10\)회를 실행한다. 페이로드 운반 설정은 1 kHz 물리 주파수가 명시되며, 모든 과제의 제어 주파수를 100 Hz로 일반화하지 않는다. 이는 Gazebo의 보편적인 기본값도 아니다.
3. **제어기와 액추에이터 지연:** 정책이 원하는 추력·회전수와 실제 적용 값은 다를 수 있다. 1차 지연 모델은 시정수 \(t_c\)가 커질수록 명령에 늦게 따라간다.
4. **벡터화 환경:** 독립 시뮬레이션을 병렬 실행하면 초당 수집하는 환경 전이 수가 늘 수 있지만, 자원 경합과 환경 내 에이전트 수에 따라 이득이 달라진다.
5. **재현성:** 같은 seed만 설정해도 비동기 전달 순서, 랜덤 초기화, 하드웨어·스레드 조건이 바뀌면 결과가 달라질 수 있다. 이 논문의 엄격한 상태 전이 경계를 먼저 이해해야 한다.

## 핵심 요약

| 논문 주장·결과 | 정확한 해석 |
| --- | --- |
| 동기식 `Server::Run(1)` 제어 | 행동에 대응하는 물리 진행과 **상태 관측**을 묶는다. 렌더링 센서 출력까지 결정론을 보장하지는 않는다. |
| 동일 조건에서 정책 재현 | hover PPO 5개 동일-seed 독립 실행의 최종 return이 `18.43 ± 0.00`, 체크포인트 해시가 100% 일치했다. 서로 다른 seed 그룹은 `18.08 ± 1.27`, 해시 일치 0%였다. |
| 높은 병렬 처리량 | 헤드리스 hover·워크스테이션·128개 환경에서 `78.58 ± 2.08`천 환경 전이/s. 노트북에서는 비교 대상 Aerial Gym의 `44.56 ± 0.42`천이 GzDRL의 `43.38 ± 0.56`천보다 높았다. |
| 시뮬레이션→실기체 | QDrone2에서 재학습 없는 정책을 9개 궤적으로 평가, 평균 유클리드 위치 오차 `20.2 ± 3.4 cm`(95% CI). 외부 OptiTrack 위치 피드백·내부 제어기를 포함한 실험이다. |

위 결과와 비교 범위는 [v1 논문의 표 II–V와 §IV–V](https://arxiv.org/html/2609.13243v1)를 따른다. `±` 표기는 표의 원래 수치를 보존하며, 서로 다른 측정량이나 장비 결과를 섞어 비교하지 않는다.

## 상세 정리

### 선행 연구와 차별점

ROS 2–Gazebo 통합은 로봇 개발에서 널리 쓰이지만, 논문이 비교한 외부 통신 기반 훈련 구성에서는 정책 호출과 물리 진행 사이의 지연·개입 스텝이 달랐다. Isaac Sim/Aerial Gym 같은 GPU 기반 시뮬레이터는 높은 병렬성에 강점이 있다. GzDRL은 Gazebo의 플러그인·물리 엔진·센서 생태계를 이용하면서 한 행동에 귀속되는 상태 전이와 CPU 병렬화를 명시적으로 제어하려는 접근이다. 이는 다른 모든 ROS 2 구성이나 GPU 시뮬레이터보다 우수하다는 일반 명제가 아니다.

### 설계와 실행 흐름

`환경 생성 → 정책 행동 → 제어기·액추에이터 → K회 단일 Gazebo 물리 스텝 → PostUpdate 상태 → 관측·보상·종료` 순서다. UAV 상태에는 위치·속도·자세 사원수·각속도가 들어간다. `AsyncDRLServerPool`은 서버별 비동기 작업자를, `GazeboPool`은 동적 작업 대기열과 부분 배치 반환, C++ 버퍼의 NumPy zero-copy view를 제공한다. 후자는 원본 버퍼의 수명과 덮어쓰기 시점에 주의가 필요하다.

### 평가 설계와 결과

- **시간 동기화:** 같은 과제·초깃값에서 ROS 2–Gazebo와 100회 측정한 행동→물리 지연, 관측 지연, 개입 물리 스텝과 궤적 분산을 비교했다. GzDRL은 다음 지정된 물리 스텝에서 행동을 적용하는 설계다.
- **재현성:** hover PPO를 동일 seed 다섯 번과 다른 seed 다섯 번 독립 실행했다. 각 실행은 8개 환경, 50만 스텝이고, 5만 스텝 간격 체크포인트를 저장했다. 평가용 20개 에피소드는 별도 프로세스·고정 seed·고정 정규화 통계에서 측정했다.
- **확장성:** 두 장비에서 환경 수를 1–128개로 바꾸며 조건마다 5회 반복, 1,000 스텝 준비 운전 후 10,000 스텝을 계측했다. 환경 수가 아닌 **완료된 환경 전이/실제 경과시간**이 처리량 단위다.
- **다중 에이전트:** 환경 32개에서 에이전트가 2, 5, 10, 20개로 늘면 GzDRL 처리량이 감소했다. 워크스테이션 20개에서는 GzDRL `3.18`천 대 Aerial Gym `5.53`천 전이/s였다.
- **도메인 무작위화:** 역진자 실험에서 질량·관성·액추에이터 시정수를 기준의 0.9–1.1배로 바꾸어 학습했다. 무작위화 평가 1,000회에서 고정조건 정책 `439.89 ± 175.97`, 무작위화 정책 `642.97 ± 232.07`의 보상을 보고한다. 이는 그 분포에 대한 시뮬레이션 실험이지 범용 실기체 전이를 증명하는 값이 아니다.
- **하드웨어:** QDrone2, Jetson Xavier NX의 100 Hz 실행, OptiTrack 120 Hz 계측으로 궤적 추적을 평가했다. 안전 이벤트·액추에이터 포화가 관측되지 않았다는 주장은 이 아홉 번의 비행 범위에 한정된다.

### 한계와 재현 시 주의

논문에 독립적인 ‘Limitations’ 절은 없다. 다음은 제시된 평가 범위에서 **이 문서가 추론한 한계**다: 상태 기반 재현성을 렌더링 이미지나 모든 플랫폼에 확대할 수 없다; 처리량은 두 장비·헤드리스·특정 UAV hover 설정에 의존한다; GPU 프레임워크와의 역전 구간이 있다; 실제 비행은 한 기체, 외부 위치추정, 아홉 궤적에 국한된다. 재현을 시도할 때 Gazebo 버전, 물리 간격, 모델·플러그인, thread 수, 시드, 체크포인트/정규화, warm-up, 측정 단위와 장비를 함께 고정해야 한다.

## 용어 정리

| 용어 | 의미 |

| GzDRL | Gazebo와 강화학습 환경을 통합한 논문의 프레임워크. |
| PPO (Proximal Policy Optimization) | 논문에서 사용한 정책경사 계열 학습 알고리즘. |
| `K` | 정책 행동 하나당 실행하는 물리 스텝 수. |

| zero-copy view | C++ 버퍼를 NumPy가 복사 없이 참조. 효율적이지만 다음 갱신에 값이 변할 수 있다. |

## 실습 학습 가이드

Python 3와 NumPy, Jupyter가 있으면 아래 노트북을 순서대로 실행할 수 있다. `python -m pip install numpy jupyter` 후 이 폴더에서 `jupyter notebook`을 실행한다. 실습은 **논문 핵심 아이디어를 작은 모형으로 검증하는 toy reproduction**이다. Gazebo, 저자 코드, 실제 PPO 훈련, ROS 2, QDrone2 실험을 실행하거나 논문 수치를 재현하는 예제가 아니다.

1. [01_foundations.ipynb](01_foundations.ipynb): UAV 고도 모형과 1차 액추에이터 지연, 1 ms 물리 간격과 `K=10` 제어 간격.
2. [02_practice.ipynb](02_practice.ipynb): 동기식 전이와 **인위적으로 주입한** 비동기 지연을 비교해 상태 궤적 분산·개입 스텝과 seed 고정 효과를 본다. ROS 2 실측과 혼동하지 않는다.
3. [03_advanced.ipynb](03_advanced.ipynb): 부분 배치 작업 스케줄링, 환경 ID 매핑, NumPy 버퍼 수명, 반복 측정의 신뢰구간. Gazebo 처리량과 무관한 모의 측정이다.
