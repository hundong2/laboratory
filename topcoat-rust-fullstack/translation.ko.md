## 쉬운 한국어 재구성

### 1. 서버 중심 렌더링

Topcoat는 기본적으로 모든 마크업을 서버에서 렌더링합니다. 컴포넌트를 비동기 Rust 함수로 작성할 수 있어 데이터베이스 같은 서버 자원을 직접 조회할 수 있습니다. 이 방식은 화면을 위해 별도의 API 계층을 반복해서 만드는 부담을 줄여 줍니다.

다만 API 계층이 코드에서 덜 보인다고 보안 경계가 없어지는 것은 아닙니다. 서버 함수에서 인증, 인가, 입력 검증과 오류 처리를 수행해야 합니다.

### 2. 별도 Wasm 번들 없는 클라이언트 반응성

`$(...)` 안에 작성한 표현식은 일반 Rust 코드처럼 타입 검사를 받습니다. 최초 페이지를 만들 때는 서버에서 평가되고, 동시에 대응하는 JavaScript로 변환되어 브라우저에서 다시 실행될 수 있습니다.

이 덕분에 단순한 토글, 카운터, 입력값 반영은 서버에 다시 요청하지 않고 처리할 수 있습니다. 별도의 Wasm 번들과 프런트엔드 빌드 단계가 필요하지 않지만, 브라우저에는 Topcoat JavaScript 런타임이 전달됩니다.

### 3. 서버 재렌더링이 필요한 갱신

검색 결과처럼 서버 데이터가 필요한 UI 조각은 `#[shard]`로 선언할 수 있습니다. shard 인자로 사용한 signal 값이 변하면 브라우저가 서버에 요청하고, 서버가 새 HTML을 렌더링해 기존 조각을 교체합니다.

shard는 HTTP 엔드포인트이므로 전달된 인자를 신뢰하면 안 됩니다. 사용자가 개발자 도구나 직접 만든 요청으로 값을 바꿀 수 있다고 가정해야 합니다.

### 4. HTML과 Rust에 가까운 템플릿

`view!` 매크로는 HTML 태그 구조 안에서 Rust의 `for`, `if`, 표현식과 컴포넌트를 사용하게 합니다. 프레임워크 전용 문자열 템플릿보다 Rust 타입 검사와 제어 흐름을 활용하기 쉽습니다.

매크로 안의 코드는 `topcoat fmt` 명령으로 포맷할 수 있습니다.

### 5. 모듈 기반 라우팅

Topcoat는 Rust 모듈 구조를 URL 트리로 연결할 수 있습니다. 예를 들어 `app/posts/id.rs` 같은 구조를 `/posts/{post_id}` 형태의 경로로 유도합니다. 별도 route 생성 빌드 단계는 필요하지 않지만 Rust 컴파일과 링크 과정 자체는 당연히 존재합니다.

필요하면 경로를 직접 선언하고 라우터에 수동 등록할 수도 있습니다.

### 6. 수정 가능한 UI 컴포넌트

Topcoat UI는 Tailwind 기반 컴포넌트를 프로젝트 안으로 복사합니다. 사용자는 복사된 소스를 직접 수정할 수 있으므로 디자인과 동작의 소유권이 애플리케이션에 남습니다.

그 대신 프레임워크의 새 버전과 로컬 수정본을 어떻게 병합할지 팀이 관리해야 합니다.

### 7. Node 없는 Tailwind 통합

`tailwind` feature를 켜면 Tailwind CSS를 Topcoat 에셋 처리와 연결할 수 있습니다. 공식 설명은 이 흐름에 Node가 필요하지 않다고 밝힙니다.

이 기능은 기본 feature 목록에 포함되지 않으므로 실제 프로젝트에서는 의존성 feature 설정을 확인해야 합니다.

### 8. 요청 컨텍스트와 웹 애플리케이션 기능

Topcoat는 요청 범위 데이터에 접근하는 `Cx`, 앱 전체에서 공유하는 context, 요청 단위 memoization을 제공합니다. cookie는 서명·암호화·접두사를 지원하며, session 모듈은 로그인·로그아웃 수명 주기, 슬라이딩 만료와 토큰 회전 같은 원시 기능을 제공합니다.

공식 로드맵에는 더 포괄적인 “Authentication”이 아직 계획 항목으로 남아 있습니다. 따라서 session 기능이 있다는 사실과 완성된 인증 제품 또는 스캐폴딩이 있다는 주장을 구분해야 합니다.

## 원문을 읽을 때 놓치기 쉬운 점

### “풀스택”의 의미

Topcoat에서 풀스택은 서버 코드와 브라우저 상호작용을 한 Rust 프로젝트 안에서 연결한다는 뜻입니다. 모든 브라우저 로직이 임의의 Rust로 실행되는 것은 아닙니다.

### “보일러플레이트 제거”의 의미

별도 API DTO와 클라이언트 호출 코드를 줄일 수 있다는 뜻이지, 네트워크 경계와 서버 검증이 사라진다는 뜻이 아닙니다. procedure와 shard는 외부 호출 가능한 API입니다.

### “빌드 단계 없음”의 의미

라우트 생성이나 JavaScript 프런트엔드용 별도 빌드가 없다는 맥락입니다. Rust 컴파일, 링크, Topcoat CLI의 에셋 번들링은 수행됩니다.

### 성숙도

공식 문서는 프로젝트를 초기·실험 단계로 분류하고 파괴적 변경을 예상하라고 안내합니다. 2026-07-30 기준 문서 버전은 `0.5.0`이며 최소 Rust `1.95`가 필요합니다.
