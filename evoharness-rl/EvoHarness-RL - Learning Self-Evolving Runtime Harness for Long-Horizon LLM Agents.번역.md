## 읽기 전 핵심 배경

장기 실행 에이전트는 현재 관찰만 보고 행동하면 이미 끝낸 일을 반복하거나, 전에 실패한 경로를 다시 선택한다. 외부 상태는 이를 완화하지만, 저장과 검색 자체도 비용이 든다. 이 논문의 질문은 “메모리를 붙일 것인가?”가 아니라 “에이전트가 외부 상태를 만들고 사용할 정책까지 학습할 수 있는가?”이다.

## 짧은 문장 대조

- **용어·약어 해설**
  - **harness policy(하네스 정책)**: 실행 중 외부 상태를 언제 읽고, 쓰고, 통합할지를 정하는 정책이다.
  - **coordination layer(조정 계층)**: 환경 행동과 외부 작업 공간 조작을 하나의 선택 과정에서 연결하는 층이다.

## 절별 한국어 해설

### 초록

긴 상호작용에서 LLM 에이전트는 상태 유지, 진행 추적, 도구 실행, 결과 검증, 과거 경험 재사용을 위해 모델 외부 지원에 의존한다. 기존 방식은 저장 내용을 만드는 규칙과 접근 시점을 프롬프트·휴리스틱으로 설계하는 경우가 많다. EvoHarness-RL은 Belief·Progress·Experience(BPE)를 정책이 직접 다룰 수 있는 상태로 노출하고, SFT와 비용 인식 GRPO를 통해 구성과 접근을 함께 학습한다. 저자들은 ALFWorld에서 Qwen3-8B가 96.9% 성공률에 도달했다고 보고하며, 학습 중 호출이 선택적으로 변하는 하네스 어닐링과 경험 상태가 압축되는 하네스 진화를 관찰한다.

### 1. 서론

문제의 핵심은 두 가지다. 첫째, 길고 잡음이 많은 상호작용 기록에서 유용한 외부 상태를 형성해야 한다. 둘째, 그 상태를 읽고 쓰는 비용을 고려해 실행 시점을 제어해야 한다. 논문은 이 둘을 분리된 후처리가 아니라 학습 가능한 하나의 정책 문제로 정의한다.

기여는 BPE 인터페이스, 하네스 행동을 포함한 지도 학습, 비용을 포함한 강화학습, 학습 과정의 어닐링·진화 분석으로 정리할 수 있다. 단순히 더 큰 메모리를 추가하는 대신 메모리와 정책 사이의 조정을 학습 대상으로 올린 점이 차별점이다.

### 2. 방법

#### 2.1 문제 정의와 외부 상태

시간 `t`의 외부 상태를 다음처럼 세 부분으로 본다.

\[
H_t = (B_t, P_t, E_t)
\]

- `B_t`: 관찰에서 추론한 현재 사실과 환경 상태
- `P_t`: 하위 목표의 완료·대기·실패 상태와 실행 이력
- `E_t`: 에피소드를 넘어 재사용하는 기술, 실패 유형, 탐색 우선순위

세 상태의 수명은 서로 다르다. Belief는 새 관찰에 빨리 바뀌고, Progress는 한 에피소드의 계획을 따라가며, Experience는 여러 에피소드에 걸쳐 느리게 통합된다. 이 분리가 오래된 관찰과 장기 기술이 같은 메모리에서 충돌하는 문제를 줄인다.

#### 2.2 정책이 사용하는 하네스 행동

정책은 환경 행동과 함께 `track`, `commit`, `recall`, `note`를 선택한다. `track`은 현재 Belief를 확인하고, `commit`은 Progress를 갱신하며, `recall`은 Experience를 검색하고, `note`는 통합 후보 경험을 남긴다. 하네스 호출도 단계 예산을 소비하므로 필요하지 않은 호출은 기회비용이 된다.

ALFWorld에서는 규칙 기반 파서가 Belief를 만들고, 제한된 하위 목표 목록이 Progress가 되며, 네 범주의 기술 은행이 Experience가 된다. 이는 범용 인터페이스와 도메인별 어댑터를 분리하려는 설계다.

#### 2.3 지도 하네스 미세조정

성공한 교사 궤적에서 환경 행동뿐 아니라 하네스 행동도 다음 행동 정답으로 학습한다. 이 단계는 모델이 호출 형식과 유용한 기록 형태를 모르는 상태에서 강화학습이 불안정해지는 것을 줄인다. 500개 훈련 게임 중 성공한 87개 궤적에서 1,153개의 행동 쌍을 구성했다.

#### 2.4 비용 인식 GRPO

보상은 과제 성공을 핵심으로 하되, 성공한 궤적의 효율, 하네스 행동 탐색, 과잉 호출, 잘못된 출력 형식을 함께 본다. 개념적으로는 다음과 같다.

\[
R = R_{success} + R_{efficiency} + R_{diversity}
    - P_{spam} - P_{format}
\]

`R_success`는 목표 달성의 엄격한 문턱이다. `R_efficiency`를 성공한 경우에만 주어 짧게 실패하는 전략을 막는다. `R_diversity`는 학습 초반 서로 다른 하네스 행동을 시험하도록 돕고 시간이 지나면 약해진다. `P_spam`은 의미 없는 반복 호출, `P_format`은 파싱할 수 없는 행동을 억제한다.

### 3. 실험

#### 3.1 설정

ALFWorld의 여섯 과제군을 사용하고 Qwen3-8B를 정책 모델로 둔다. 에피소드 한도는 70단계다. Belief 48항목, Progress 8개 하위 목표, Experience 범주당 80개, 범주별 검색 상위 3개라는 제한을 둔다. GRPO는 150에포크, 그룹 크기 8, 학습률 `1e-6`으로 수행되며 논문은 H200 GPU 8장을 보고한다.

#### 3.2 주요 비교

본 140과제 분할에서 평균 성공률은 ReAct 47.9%, 추론 시점 BPE를 붙인 EvoHarness-Base 56.4%, SFT 68.6%, 최종 RL 96.9%다. 결과는 학습하지 않은 외부 상태만으로도 이점이 있지만, 상태 형성과 접근 시점을 함께 학습할 때 상승 폭이 크다는 저자 주장을 지지한다.

#### 3.3 구성요소 제거

학습하지 않은 BPE 하네스에서 전체 성공률은 56.4%다. Belief 제거 시 55.0%, Progress 제거 시 50.7%, Experience 제거 시 48.6%다. 이 설정에서는 경험 저장소의 영향이 가장 컸고, Progress는 여러 하위 목표가 필요한 과제에서 특히 중요했다.

#### 3.4 미관측 과제

미관측 분할에서는 ReAct 50.0%, 추론 시점 BPE 77.6%, SFT 69.4%, 최종 RL 86.6%를 기록했다. SFT가 단순 BPE보다 낮다는 점은 성공 교사의 특정 행동 순서를 모방하는 것만으로는 일반화가 충분하지 않음을 시사한다.

### 4. 학습 동역학 분석

#### 4.1 하네스 어닐링

초기 정책은 외부 상태를 자주 확인하고 갱신한다. 학습이 진행되면 반복되는 조정 패턴 일부가 모델 정책에 내재화되고, 하네스 호출은 필요한 순간으로 좁혀진다. 논문의 곡선에서는 호출량이 감소한 뒤 에피소드당 대략 한 번 수준에서 안정된다. 이는 하네스가 사라지는 것이 아니라 선택적으로 사용되는 상태다.

#### 4.2 하네스 진화

Experience 기술 은행은 처음에 빠르게 늘지만 이후 중복 항목을 합치고 오래되거나 잘못된 항목을 제거하면서 안정된다. 새 관찰이 검색된 과거 지식과 충돌하면 현재 근거를 우선하고 수정 내용을 기록한다. 이 과정은 단순 누적 메모리와 달리 기억 품질을 학습 과정의 일부로 본다.

### 5. 관련 연구

논문은 장기 에이전트 메모리, 경험 재사용, 도구 사용, 강화학습 기반 에이전트 개선과 연결된다. 기존 연구 다수가 저장 구조 또는 프롬프트 전략에 집중했다면, 이 연구는 외부 작업 공간에 대한 읽기·쓰기를 정책 행동 공간에 포함하고 비용까지 최적화하는 데 초점을 둔다.

### 6. 결론

저자들은 장기 에이전트 성능이 도구나 메모리의 존재만이 아니라 그것을 구성하고 조정하는 학습 가능한 정책에 달려 있다고 결론짓는다. BPE는 이 아이디어를 구현하는 하나의 구체적 분해이며, 다른 환경에 적용하려면 도메인 어댑터와 안전한 상태 수명 주기가 필요하다.

## 그림과 표 읽기

- **그림 1**: 정책, 환경, BPE 하네스가 어떻게 순환하는지 보여 준다. 환경 행동과 하네스 행동이 같은 정책 선택에 놓인 점을 본다.
- **그림 2**: 성공 교사 궤적 SFT에서 비용 인식 GRPO로 이어지는 두 단계 훈련 흐름이다.
- **표 1**: 여러 장기 에이전트 기준선과 본 분할 성공률을 비교한다. 모델·교사·추가 메모리 조건이 서로 다를 수 있어 숫자만으로 순위를 일반화하면 안 된다.
- **표 2**: B/P/E 제거 결과다. 하나의 구성요소 효과가 과제군마다 다름을 함께 읽어야 한다.
- **그림 3·5**: 전체 및 행동별 하네스 호출이 학습 중 감소하는 어닐링을 보여 준다.
- **그림 4**: Experience 항목 수가 성장한 뒤 통합으로 안정되는 과정을 보여 준다.
- **그림 6**: 성공·효율·벌점이 합쳐진 훈련 보상의 변화를 보여 주므로 성공률 곡선과 동일시하지 않는다.

## 부록 해설

### 부록 A: 구현 세부

상태 용량, 검색 상위 `k`, LFU 퇴출, GRPO 배치와 최적화 설정을 제공한다. Experience의 새 항목은 사용 횟수 1로 시작하고, 범주별 최대 80개를 유지한다. 이 설정은 재현의 출발점이지만 코드·시드가 없으면 완전한 동일 재현을 보장하지 않는다.

### 부록 B: 학습 동역학

행동 종류별 호출과 보상 항의 변화가 추가된다. 모든 하네스 행동이 같은 속도로 줄지 않으며, 상태 읽기와 쓰기의 필요 시점이 다름을 보여 준다.

### 부록 C: 정성 사례

주전자 청소 과제에서 Progress 확정, Experience 검색, 환경 행동, 새 통찰 기록이 연결된다. 과거 위치 정보가 현재 관찰과 충돌할 때 현재 관찰을 따르고 잘못된 경험을 수정하는 장면이 핵심이다.

### 부록 D: 프롬프트와 프로토콜

교사 데이터 생성, 상태 갱신, 경험 통합에 사용한 지침과 행동 형식을 설명한다. 실제 제품에서는 이 프롬프트를 그대로 복사하기보다 상태 스키마, 권한, 출처, 만료 정책을 먼저 정의해야 한다.
