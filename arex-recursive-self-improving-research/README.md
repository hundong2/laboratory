## 한눈에 보기

AREX의 핵심은 "더 오래 검색하기"가 아니라 "현재 답을 검증해 다음 검색 문제를 더 잘 만드는 것"이다.

```text
질문
  -> 내부 연구 루프: 검색 -> 관찰 -> 후보 갱신 -> 임시 답변
  -> 외부 자기개선 루프: 제약별 검증
       -> ACCEPT: 충분히 검증됨
       -> REFINE: 유효한 증거를 보존하고 미해결 제약만 재조사
       -> RESTART: 현재 궤적이 복구 불가능하면 처음부터 재조사
```

긴 연구 과정에서는 `update_context`가 검증된 증거, 인용, 탈락한 후보, 미해결 제약, 다음 계획을 압축 상태로 남긴다. 단순 요약이 아니라 다음 행동을 결정하기 위한 연구 상태 갱신이다.

## 기초 개념

### Deep Research 에이전트

한 번의 모델 응답으로 끝내지 않고 검색, 문서 열람, 비교, 검증, 인용을 반복해 답을 만드는 에이전트다. 어려움은 검색량보다 여러 조건을 동시에 만족하는 답을 찾고 증거를 일관되게 유지하는 데 있다.

### 발견-검증 비대칭

정답 후보를 넓은 공간에서 발견하는 일은 비싸지만, 주어진 후보가 조건 하나를 만족하는지 확인하는 일은 상대적으로 작게 나눌 수 있다. AREX는 이 비대칭을 이용해 임시 답을 제약별로 감사하고 실패한 제약만 다음 연구 목표로 바꾼다.

### 연구 상태

연구 상태는 대화 기록 전체가 아니다. 현재까지 검증된 사실, 출처, 유효한 후보, 반증된 후보, 충돌, 미해결 조건, 다음 행동을 담은 의사결정용 표현이다. 좋은 상태는 짧으면서도 근거의 출처와 부정적 결과를 잃지 않아야 한다.

## 연구 질문과 핵심 기여

### 연구 질문

1. 여러 제약을 동시에 만족해야 하는 Deep Research를 재귀적 개선 문제로 만들 수 있는가?
2. 긴 궤적에서 중요한 증거와 실패를 잃지 않으면서 컨텍스트를 줄일 수 있는가?
3. 최종 보상만 있는 긴 에이전트 궤적에서 결정적인 중간 단계를 더 잘 학습할 수 있는가?

### 핵심 기여

1. 검증을 최종 필터가 아니라 연구 라운드 사이의 상태 전이로 사용한다.
2. 내부 연구 루프와 외부 제약별 자기개선 루프를 결합해 `ACCEPT`, `REFINE`, `RESTART`를 선택한다.
3. 외부 요약 모델 없이 에이전트가 직접 호출하는 자율 컨텍스트 갱신(ACU)을 학습한다.
4. 검증 가능한 합성 과제와 품질 관리된 교사 궤적에 단계적 agentic mid-training과 장기 강화학습을 적용한다.
5. 증거 발견, 잘못된 경로의 기각과 전환, 핵심 컨텍스트 갱신 같은 key step에 학습 신호를 집중한다.

## 방법

### 1. 내부 연구 루프

라운드 \(k\), 단계 \(t\)의 궤적은 다음과 같다.

\[
h_t^{(k)} = [(m_i^{(k)}, a_i^{(k)}, o_i^{(k)})]_{i=1}^{t}
\]

- \(m_i\): 모델의 중간 분석
- \(a_i\): 검색, 방문, 상태 갱신, 종료 같은 행동
- \(o_i\): 도구가 반환한 관찰

정책 \(\pi_\theta\)는 원 질문 \(x\), 현재 연구 목표 \(q^{(k)}\), 유효 컨텍스트를 보고 다음 분석과 행동을 만든다. 출처가 충돌하면 권위, 직접성, 시간적 유효성을 기준으로 더 강한 증거를 찾는다.

### 2. 자율 컨텍스트 갱신

\[
z_t^{(k)} = f_\theta(h_t^{(k)})
\]

`update_context`가 만든 \(z_t^{(k)}\)에는 다음 정보가 남아야 한다.

- 검증된 발견과 source ID
- 현재 후보와 후보별 상태
- 미해결 제약과 유효성 우려
- 기각된 후보와 기각 이유
- 다음 단계의 구체적 계획

가장 최근 갱신이 \(\tau\)에서 일어났다면 이후 정책은 압축 상태와 \(\tau\) 이후 새 상호작용만 본다. 고정 토큰 임계값 요약과 달리 의미 있는 연구 상태 전환 시점에 모델이 스스로 갱신한다.

### 3. 구조화된 종료

내부 루프는 다음 튜플을 외부화한다.

\[
r^{(k)} = (y^{(k)}, \mathcal{E}^{(k)}, s^{(k)})
\]

- \(y^{(k)}\): 임시 답변
- \(\mathcal{E}^{(k)}\): 뒷받침 증거
- \(s^{(k)}\): 0부터 100 사이의 답변 수준 신뢰도

### 4. 외부 자기개선 루프

외부 평가는 복구 가능성 \(v^{(k)}\), 보존할 정보 \(P^{(k)}\), 남은 문제 \(I^{(k)}\), 다음 목표 \(q^{(k+1)}\)를 만든다.

- `ACCEPT`: \(s^{(k)} \ge \tau\)
- `REFINE`: \(s^{(k)} < \tau\)이고 현재 궤적이 복구 가능
- `RESTART`: \(s^{(k)} < \tau\)이고 현재 궤적이 복구 불가능

최대 라운드는 제한되어 있다. 임계값을 넘는 답이 없으면 완료된 답 중 신뢰도가 가장 높은 것을 반환한다. 자기 신뢰도 보정이 잘못되면 조기 종료나 불필요한 재시작을 일으킬 수 있다.

## 학습 데이터와 훈련

### 데이터 구성

논문은 검색 집약형, 추론 집약형, 과학 문헌형의 세 종류 과제를 합성한다. 잠재 답 \(y\)에서 검증 가능한 제약 집합 \(\mathcal{C}(y)=\{c_1,\ldots,c_n\}\)을 만들고 답을 직접 노출하지 않는 간접 제약으로 바꾼다. 자동 필터는 정답성, 유일성, 증거 가용성, 난도를 검사한다.

교사 궤적에서는 추측, 잘못된 도구 호출, 관찰 무시, 근거 없는 주장과 인용, 낮은 신뢰도의 결과를 제거한다.

### 단계적 agentic mid-training

1. 검색과 웹 탐색이 많은 다중 라운드 궤적으로 도구 사용을 학습한다.
2. 전문가 수준 추론 데이터로 가설 비교와 장기 추론을 강화한다.
3. 추론 특화가 검색 능력을 약화시키는 간섭을 줄이기 위해 검색, 추론, 도구 사용을 다시 혼합한다.

### Key-step focused replay

성공하고 최종 검증을 통과한 궤적에서만 다음 단계를 선택해 재학습한다.

- 탐색 뒤 처음으로 답과 관련된 증거를 얻은 단계
- 잘못된 가설을 처음 기각하고 방향을 바꾼 단계
- 검증된 증거, 미해결 제약, 다음 계획을 보존한 핵심 컨텍스트 갱신

step-loss 분석에서 일반 단계는 0.232, 증거 발견 0.277, 경로 기각/전환 0.298, 핵심 컨텍스트 갱신 0.300이었다. 결정적인 단계가 더 어렵다는 관찰을 key-step 강화의 근거로 사용한다.

### Step-aware 강화학습

토큰별 확률비를 한 assistant step 안에서 기하평균한 뒤 step을 궤적 안에서 평균하고 마지막으로 궤적을 평균한다. 긴 궤적이 토큰 수만으로 목적함수를 지배하지 않게 하는 계층적 정규화다. 최종 결과 보상에 더해 성공한 궤적의 key step에만 제한된 보너스를 준다.

## 실험과 결과

### 모델과 평가

- AREX-Turbo: Qwen3.5-4B 기반 dense 모델
- AREX-Base: Qwen3.5-122B-A10B 기반 MoE, 총 122B 중 10B 활성
- 도구: `search`, `visit`, `update_context`, `finish`; HLE에서는 Python 추가
- 한도: 내부 루프 최대 300 turn, 외부 루프 최대 5회
- 벤치마크: BrowseComp, GAIA, xbench-2510, DeepSearchQA, WideSearch-en, HLE with tools

| 모델 | BrowseComp | GAIA | xbench-2510 | DeepSearchQA | WideSearch-en | HLE(tool) |
|---|---:|---:|---:|---:|---:|---:|
| AREX-Turbo | 70.7 | 81.6 | 57.0 | 78.5 | 68.5 | 40.6 |
| AREX-Base | 82.5 | 85.4 | 71.0 | 89.9 | 82.0 | 52.4 |
| Qwen3.5-122B | 63.8 | 81.6 | - | - | 60.5 | 47.5 |
| Qwen3.5-397B | 78.6 | 83.5 | 61.0 | 82.1 | 74.0 | 48.3 |

WideSearch-en은 Item-F1, DeepSearchQA는 F1, 나머지는 주로 정확도를 사용하므로 열 사이 숫자를 같은 의미로 비교하면 안 된다. 논문 표의 별표가 붙은 HLE 결과는 전체 세트, 별표가 없는 결과는 text-only subset이므로 모든 HLE 수치를 직접 순위화할 수 없다.

### ACU와 외부 루프의 효과

| ACU | 외부 루프 | BrowseComp 정확도 |
|---|---|---:|
| 없음 | 없음 | 59.6 |
| 없음 | 있음 | 69.8 |
| 있음 | 없음 | 71.4 |
| 있음 | 있음 | 82.5 |

두 구성 요소를 모두 제거한 설정과 전체 AREX의 차이는 22.9%p다. 단일 벤치마크 ablation이라는 범위는 기억해야 한다.

BrowseComp의 80.3% 사례에서 ACU가 호출됐다. 평균 갱신 시점은 25,721 token, 중앙값은 25,386 token이었고 128K 상한에 도달한 호출은 0.01%뿐이었다. 미해결 제약은 갱신 내용의 95.5%, 다음 계획은 96.4%, 기각 후보는 81.5%에 포함됐다.

### 훈련 ablation

| 변경 | BrowseComp 정확도 |
|---|---:|
| 전체 AREX | 82.5 |
| 단계적 훈련 대신 직접 혼합 | 77.5 |
| key step 대신 무작위 step replay | 74.1 |
| step-aware RL 대신 표준 GRPO | 79.4 |

부록의 단순화된 self-distillation 실험은 52.3에서 57.1로 개선됐지만 ACU, 외부 루프, key-step supervision을 제외한 예비 실험이다.

## 비판적으로 읽기

1. **자기 신뢰도는 검증기가 아니다.** confidence 분포가 정답과 오답을 어느 정도 분리하지만 calibration error나 임계값 민감도는 충분히 제시되지 않았다.
2. **비용 비교가 부족하다.** 최대 300 turn과 5개 외부 라운드의 검색 호출 수, 지연, 토큰과 금전 비용 비교가 필요하다.
3. **웹 재현성이 낮다.** 검색 결과와 페이지 내용은 시간에 따라 달라진다.
4. **평가 조건이 완전히 같지 않을 수 있다.** 비공개 모델의 prompt, 도구, budget 차이와 HLE subset 차이를 통제해야 한다.
5. **검증 오류가 재귀될 수 있다.** 잘못 검증된 사실을 압축 상태에 보존하면 이후 라운드가 오류를 강화할 수 있다.
6. **합성 데이터 편향이 있다.** 자동 검증 가능한 과제가 실제 연구의 모호성과 불완전한 출처를 충분히 대표하지 않을 수 있다.
7. **안전한 탐색은 별도 과제다.** 악성 웹 문서, prompt injection, 출처 위조, 개인정보와 라이선스 방어는 중심 평가가 아니다.

## 재현 시 주의점

- 공개 모델의 실제 라이선스, checkpoint, tokenizer와 chat template은 모델 카드에서 다시 확인한다.
- 검색 공급자, 날짜, 지역, tool schema, turn budget, 외부 루프 임계값을 고정해 기록한다.
- 정답 평가와 제약별 검증을 같은 모델 하나에 맡기면 오류가 상관될 수 있다. 규칙 기반 검사, 독립 모델, 사람 검토를 혼합한다.
- confidence를 확률로 해석하려면 held-out calibration set에서 reliability diagram, ECE, Brier score를 측정한다.
- `update_context`가 근거 URL, 날짜, 인용 범위, 반증 이유를 보존하는지 회귀 테스트한다.
- 본 실습은 논문 checkpoint나 비공개 학습 데이터를 재현하지 않는 toy reproduction이다.

## 용어 정리

| 용어 | 의미 |
|---|---|
| RSI (Recursively Self-Improving) | 이전 라운드의 부분 검증 결과를 다음 문제와 상태로 바꾸어 반복 개선하는 과정 |
| ACU (Autonomous Context Updating) | 모델이 필요 시점을 정해 연구 궤적을 의사결정 가능한 압축 상태로 갱신하는 기능 |
| constraint-wise verification | 답이 만족해야 할 조건을 각각 분리해 근거와 함께 검사하는 방법 |
| recoverable trajectory | 오류가 있어도 유효한 증거와 진행 상태를 보존해 수정할 수 있는 연구 궤적 |
| key step | 최종 성공에 중요한 증거 발견, 오류 기각, 상태 갱신 단계 |
| MoE (Mixture-of-Experts) | 입력마다 일부 expert만 활성화해 총 parameter와 실제 계산량을 분리하는 구조 |
| calibration | 모델이 말한 confidence와 실제 정답 빈도가 일치하는 정도 |

## 실습 학습 가이드

실습은 외부 패키지 없이 Python 표준 라이브러리로 실행할 수 있으며 논문의 전체 시스템이 아닌 핵심 메커니즘의 toy reproduction이다.

1. [01_foundations.ipynb](01_foundations.ipynb): 제약별 검증과 `ACCEPT`/`REFINE`/`RESTART`
2. [02_practice.ipynb](02_practice.ipynb): 검증 사실, 탈락 후보, 미해결 조건을 보존하는 ACU
3. [03_advanced.ipynb](03_advanced.ipynb): step별 기하평균 확률비, 계층 평균, key-step advantage
