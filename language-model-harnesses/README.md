## 한눈에 보기

글의 핵심 주장은 "더 좋은 일반화가 항상 더 큰 Transformer 내부에서만 나올 필요는 없고, 모델 주변의 프로그램인 하네스에도 일반화 능력이 들어갈 수 있다"는 것이다.

여기서 하네스는 외부 세계의 긴 상태, 도구 출력, 문서, 코드베이스, 이전 행동을 언어 모델이 처리할 수 있는 관찰 단위로 바꾸고 다음 행동을 결정하는 프로그램이다. 좋은 하네스는 전체 과제가 분포 밖(out-of-distribution)이더라도 각 언어 모델 호출이 익숙한 형태의 작은 관찰, 즉 locally in-distribution(LID)을 보도록 만든다.

원문은 Recursive Language Model(RLM) 하네스를 예로 든다. RLM은 입력별 문맥을 변수로 오프로딩하고, 도구와 서브 에이전트 호출을 코드 REPL의 함수처럼 다루어 루트 모델의 문맥에 작업별 세부사항이 직접 쌓이지 않게 한다. 이 설계가 서로 다른 길이와 도메인의 과제를 비슷한 루트 궤적으로 보이게 만들고, 그 결과 학습된 분해 전략이 더 잘 전이된다는 실험 결과를 제시한다.

## 기초 개념

### 조합적 일반화

조합적 일반화는 훈련에서 본 개별 패턴을 조합해 처음 보는 문제를 푸는 능력이다. 예를 들어 짧은 문서에서 "조건에 맞는 항목을 찾고 집계한다"는 방법을 배운 시스템이 훨씬 긴 문서나 다른 도메인의 표에도 같은 전략을 적용한다면 조합적 일반화가 일어난 것이다.

### 하네스

하네스는 모델 호출 앞뒤에 있는 실행 프로그램이다. 프롬프트를 만들고, 도구를 호출하고, 결과를 저장하고, 어떤 다음 행동을 할지 결정한다. 에이전트 시스템에서 하네스는 단순한 부가 코드가 아니라 모델이 어떤 문제를 어떤 모양으로 보게 할지 결정하는 구조적 편향이다.

### Locally In-Distribution

Locally in-distribution은 전체 과제는 길고 복잡해도, 각각의 언어 모델 호출은 학습 중에 본 것과 비슷한 짧고 익숙한 입력을 받는 상태를 말한다. 긴 상태 전체를 한 번에 문맥에 밀어 넣는 대신, 작은 부분 문제로 나누면 개별 호출은 더 안정적일 수 있다.

### Context Offloading

컨텍스트 오프로딩은 긴 입력이나 도구 출력을 루트 프롬프트에 직접 붙이지 않고 변수, 파일, 메모리, REPL 상태 같은 외부 저장소에 둔 뒤 필요한 함수 호출에만 넘기는 방식이다. 이러면 루트 모델은 도메인별 세부 텍스트보다 "어떻게 분해할 것인가"라는 구조를 주로 보게 된다.

### Programmatic Sub-Agent Calling

프로그램식 서브 에이전트 호출은 서브 모델, 검색기, 계산기, 파서 같은 구성요소를 함수처럼 호출하고 결과를 변수에 저장하는 방식이다. 도구 출력 전체를 대화 문맥에 계속 누적하지 않으므로 문맥 팽창과 context rot 위험을 줄일 수 있다.

## 핵심 요약

- 기존 post-training은 더 많은 환경, 더 긴 롤아웃, 더 큰 문맥을 모으는 방향으로 확장되어 왔다.
- 원문은 Transformer 자체가 조합적 일반화에 항상 충분히 강하지 않으므로, 하네스가 더 높은 수준의 귀납적 편향을 제공해야 한다고 주장한다.
- 좋은 하네스는 복잡한 상태 `s`를 여러 작은 관찰 `o`로 바꾸어 각 LM 호출이 익숙한 형태의 문제만 다루게 한다.
- RLM 하네스는 컨텍스트 오프로딩과 프로그램식 서브 호출을 통해 서로 다른 과제가 루트 모델에게 거의 같은 실행 궤적으로 보이게 만든다.
- 원문 실험은 Qwen3-30B-A3B-Instruct-2507을 RLM과 일반 Transformer 방식으로 비교했다.
- 짧은 과제에서만 학습한 RLM이 8-32배 긴 평가 과제로 전이했고, 같은 train lift 대비 약 10배 수준의 eval lift를 보였다고 보고한다.
- 서로 다른 도메인이라도 분해 전략이 비슷하면 RLM의 전이 성능이 일반 Transformer보다 더 잘 유지되는 경향을 보였다.
- RLM 학습은 단순 Transformer 학습보다 런타임과 메모리 비용이 더 들 수 있지만, 긴 문맥 전체를 직접 학습하는 비용에 비하면 더 나은 확장 경로가 될 수 있다.

## 상세 정리

### 1. 문제의 출발점

현대 언어 모델은 긴 문맥, 도구 사용, 체인 오브 소트, 에이전트 루프를 통해 더 어려운 과제를 풀고 있다. 그러나 모든 정보를 하나의 계속 길어지는 프롬프트에 붙이는 방식은 모델 호출을 훈련 분포에서 멀어지게 만든다. 원문은 이 현상을 context rot과 연결해 설명한다.

중요한 관점 전환은 "전체 과제를 모델이 직접 일반화해야 한다"가 아니라 "하네스가 전체 과제를 모델이 이미 잘하는 작은 호출들의 조합으로 바꿔야 한다"는 것이다.

### 2. 하네스가 일반화 구조를 만든다

하네스는 외부 상태와 모델 사이에 있는 함수처럼 볼 수 있다. 좋은 하네스는 도메인별 텍스트를 줄이고, 루트 모델이 분해 계획과 제어 흐름을 보게 한다. 그러면 서로 다른 과제도 같은 구조를 공유할 때 루트 모델의 관점에서는 같은 종류의 문제처럼 보인다.

원문은 이를 하네스가 과제 궤적 위에 등가 관계를 유도한다고 표현한다. 엄밀한 수학적 정의라기보다, 비슷한 문제들을 비슷한 토큰 궤적으로 접어 넣는다는 직관이 핵심이다.

### 3. RLM의 두 핵심 장치

첫째, 컨텍스트 오프로딩은 입력별 문맥을 루트 프롬프트 밖에 둔다. 루트 모델은 긴 원문 대신 `DATA`, `QUERY`, `RESULTS` 같은 참조를 보고 작업을 분해한다.

둘째, 프로그램식 서브 호출은 도구 출력과 서브 에이전트 응답을 루트 문맥에 그대로 되돌려 붙이지 않는다. 결과는 변수에 저장되고, 이후 함수나 서브 호출에 전달된다. 루트 모델은 "부분 문제를 호출하고 집계한다"는 구조를 유지한다.

### 4. 길이 일반화 실험

원문은 MRCRv2, GraphWalks, LongBenchPro, OOLONG, OOLONG-Pairs, Ada-LEval 등 길이가 달라지는 여섯 환경에서 짧은 split으로만 학습하고 더 긴 split에서 평가한다. 모델은 Qwen3-30B-A3B-Instruct-2507이며, RLM, 분해 힌트를 준 RLM, YaRN을 적용한 base Transformer를 비교한다.

핵심 관찰은 RLM이 짧은 과제에서 배운 분해 전략을 더 긴 과제에도 적용했다는 점이다. 반면 base Transformer는 훈련 보상은 올라가도 긴 평가에서 개선이 제한적인 경우가 많았다.

### 5. 전략 일반화 실험

길이뿐 아니라 도메인이 달라도 underlying strategy가 비슷한 경우 전이를 관찰한다. 예로 OOLONG의 TREC 질문 집계에서 spam/ham 질문 집계로, OBLIQ-Bench의 글쓰기 도메인에서 수학 도메인으로, Twitter stance 검색에서 Wildchat 오류 검색으로 옮겨 평가한다.

표면 토큰 분포는 다르지만 "검색하고, 비교하고, 집계한다" 같은 잠재 구조가 비슷하면 RLM이 더 나은 전이를 보인다는 것이 원문의 주장이다.

### 6. 실패 가능성과 설계 주의점

RLM이라고 항상 일반화가 보장되지는 않는다. 짧은 과제에서는 전체 문제를 하나의 서브 호출로 던져도 성공할 수 있다. 하지만 긴 과제에서는 그 서브 호출 자체가 분포 밖이 되어 실패할 수 있다. 따라서 하네스는 단순히 문맥을 숨기는 데서 끝나지 않고, 작은 부분 문제로 안정적으로 쪼개는 전략을 학습하거나 유도해야 한다.

원문은 때로는 "분해하라"는 힌트나 감독 신호가 샘플 효율을 높일 수 있다고 본다.

### 7. 실무 적용 관점

실무 에이전트나 도구형 LLM 시스템을 설계할 때는 다음 질문이 중요하다.

- 루트 모델 문맥에 도메인별 원문과 도구 출력이 계속 누적되고 있는가?
- 긴 입력이 변수, 파일, 검색 인덱스, 데이터프레임, 캐시 등으로 오프로딩되는가?
- 모델이 보는 각 호출은 짧고 익숙한 작업인가?
- 서브 호출 결과를 모두 다시 프롬프트에 붙이는 대신 필요한 요약, 식별자, 변수만 전달하는가?
- 짧은 과제에서 배운 계획이 긴 과제와 다른 도메인에도 같은 실행 구조로 유지되는가?

## 용어 정리

| 용어 | 의미 |
| --- | --- |
| Harness | 모델과 외부 환경 사이에서 프롬프트, 도구 호출, 상태 저장, 행동 선택을 조정하는 프로그램 |
| RLM | Recursive Language Model. 컨텍스트 오프로딩과 재귀적 서브 호출을 사용하는 하네스 구조 |
| Compositional Generalization | 익숙한 작은 개념과 절차를 조합해 처음 보는 문제를 푸는 능력 |
| Locally In-Distribution | 각 개별 모델 호출이 훈련 중에 본 것과 비슷한 관찰을 받는 상태 |
| OOD | Out-of-distribution. 훈련 분포에서 벗어난 입력 또는 과제 |
| Context Offloading | 긴 입력과 중간 결과를 루트 프롬프트 밖의 변수나 저장소에 두는 방식 |
| Programmatic Sub-Agent Calling | 서브 에이전트와 도구를 함수 호출처럼 다루고 결과를 프로그램 상태에 저장하는 방식 |
| Trajectory Isomorphism | 서로 다른 과제의 루트 실행 궤적이 구조적으로 거의 같아지는 현상 |
| Context Rot | 긴 문맥 누적으로 모델 행동이 불안정해지는 현상 |
