## 한눈에 보기

이 논문은 영업 대화의 매 턴에서 최종 전환 확률을 갱신하고 영업 담당자에게 전략적 안내를 제공하는 시스템인 **SalesRLAgent**를 제안한다. 핵심 재료는 GPT-4O로 만든 합성 대화, 3,072차원 Azure OpenAI 임베딩, 대화 이력과 영업 특징을 합친 상태 표현, 확률을 출력하는 정책 네트워크, 가치 네트워크, 그리고 유사도·앙상블 일관성 등을 이용한다는 신뢰도 모듈이다.

논문이 다루는 문제 자체는 중요하다. 최종 결과 하나만 예측하는 대신 대화 접두사(prefix)마다 확률을 갱신하고, 분포 밖 입력에서는 낮은 신뢰도를 표시하려는 방향은 실제 제품에 유용하다. 그러나 v1은 강화학습 알고리즘, 보상식, 전이 정의, 네트워크 크기, 데이터 분할, 난수 시드, 기준 모델 설정, 통계적 불확실성을 공개하지 않는다. 공개된 6쪽 문서만으로 96.7% 정확도나 43.2% 전환율 증가를 재현하거나 인과 효과로 확정할 수 없다.

핵심 판정은 다음과 같다.

1. **아이디어 가치**: 턴별 확률·불확실성·실시간 개입을 한 파이프라인으로 보려는 문제 설정은 학습 가치가 있다.
2. **방법 명료성**: v1의 수학적·구현적 정의는 부족하다. 특히 이것이 전형적인 강화학습인지 순차 지도학습인지 구분할 정보가 모자란다.
3. **평가 신뢰도**: 수치는 크지만 분할 방식, 반복 실험, 신뢰구간, 원시 결과가 없어 증거 강도를 판단하기 어렵다.
4. **현장 배포**: 개인정보, 편향, 인간 감독, 확률 보정, 분포 이동과 실험 설계가 해결되기 전에는 자동 의사결정 도구로 사용하면 안 된다.

## 기초 개념

### 전환 예측

전환(conversion)은 잠재 고객이 구매·계약·데모 신청 같은 목표 행동을 완료했는지를 뜻한다. 대화가 `x_1, x_2, ..., x_t` 순서로 진행될 때 턴 `t`의 예측 목표는 보통 다음과 같다.

\[
\hat p_t = P(Y=1 \mid x_{1:t})
\]

여기서 `Y=1`은 최종 전환을 뜻한다. 이 값은 단순 분류 라벨이 아니라 **보정된 확률**이어야 한다. 예를 들어 0.8로 예측한 사례 100개 중 실제 전환이 약 80개여야 업무 의사결정에 쓸 수 있다.

### 순차 예측과 강화학습의 차이

대화 이력을 사용하는 것만으로 자동으로 강화학습이 되는 것은 아니다.

- **순차 지도학습**은 과거 대화를 입력으로 받아 정답 전환 여부나 확률을 예측한다.
- **강화학습**은 에이전트의 행동이 다음 상태와 누적 보상에 영향을 주는 환경에서 정책을 학습한다.
- **문맥적 밴딧**은 한 시점의 문맥을 보고 행동을 선택하고 즉각 보상을 받는다.
- **오프라인 강화학습**은 이미 수집된 행동 로그를 이용하므로 행동 정책과 커버리지, 반사실적 평가가 중요하다.

논문은 상태를 대화 표현, 행동을 전환 확률, 보상을 예측 정확도로 정의한다. 확률 출력이 고객이나 다음 대화 상태를 바꾸지 않고 정답과 비교되는 구조라면, 이는 정책 최적화라기보다 순차 확률 예측에 더 가깝다. 강화학습 주장을 성립시키려면 환경 전이 `P(s_{t+1}|s_t,a_t)`, 행동이 환경에 미치는 영향, 보상 `r_t`, 할인율, 종료 조건, 행동 정책과 학습 알고리즘이 명시되어야 한다.

### 판별력과 보정

- **정확도(accuracy)**: 임계값 뒤의 정답 비율이다. 클래스 비율과 임계값에 민감하다.
- **AUC-ROC**: 양성을 음성보다 높게 순위화할 가능성을 측정한다. 확률 보정 여부는 알려주지 않는다.
- **로그 손실(log loss)**과 **Brier 점수**: 예측 확률의 품질을 평가한다.
- **ECE (Expected Calibration Error)**와 신뢰도 곡선: 예측 확률과 관측 빈도의 일치를 본다.

이 시스템처럼 “전환 확률”을 직접 보여 주는 제품에서는 정확도와 AUC만으로 충분하지 않다.

### 합성 데이터와 분포 이동

합성 대화는 개인정보 부담을 줄이고 희귀 상황을 만들기 쉽다. 반면 생성 모델의 말투, 상식, 라벨 규칙과 고정관념을 그대로 학습할 수 있다. 같은 생성기와 프롬프트로 만든 학습·시험 자료는 실제 대화보다 서로 닮아 성능이 과대평가될 수 있다. 산업, 기업, 상품, 국가, 언어, 채널과 시점이 바뀌는 **분포 이동**을 별도로 시험해야 한다.

## 연구 질문과 핵심 기여

### 연구 질문

논문을 검증 가능한 질문으로 다시 쓰면 다음과 같다.

1. 대화 이력을 포함한 전문 모델이 범용 LLM 프롬프트와 전통 분류기보다 최종 전환을 더 잘 예측하는가?
2. 매 턴의 확률 변화가 실제 전환 가능성을 잘 반영하고, 확률 자체가 보정되어 있는가?
3. 낯선 대화에서 신뢰도를 낮추는 장치가 오류를 탐지하는가?
4. 실시간 안내가 **예측**을 넘어 실제 영업 결과를 **인과적으로 개선**하는가?
5. 전체 입력·임베딩·특징·안내 생성까지 포함해 100ms 이내에 안정적으로 동작하는가?

### 논문이 제시한 기여

논문은 다음을 기여로 제시한다.

- 영업 대화를 순차 의사결정 문제로 다루는 전문 강화학습 아키텍처
- GPT-4O 다중 에이전트와 15개 산업 시나리오를 이용한 합성 데이터 생성
- Azure OpenAI 3,072차원 임베딩과 영업 도메인 특징을 결합한 상태 표현
- 학습 자료 유사도, 앙상블 일관성, 새로운 패턴 탐지를 이용한다는 신뢰도 추정
- 캐시, 증분 상태 갱신, 양자화, 오케스트레이션과 CRM 연동
- 전통 ML, LLM, 익명 상용 시스템과의 비교 및 현장 A/B 테스트

이 목록은 **구현 완료와 유효성이 독립 검증됐다는 뜻이 아니라 논문이 선언한 범위**다.

### 선행 연구와의 차이

논문은 RAG 기반 영업 도우미를 정보 검색·생성 중심으로, SalesRLAgent를 턴별 확률 추적·전략 안내 중심으로 대비한다. 대화 정책 강화학습과 구매 의도 예측 연구도 인용한다. 다만 선행 연구 검토가 짧고, 비교 대상의 입력·학습 자료·제품 기능이 동일하지 않다. 특히 참고문헌 [5]는 [뉴스 요약 LLM 벤치마크](https://arxiv.org/abs/2301.13848)여서 영업 대화 아키텍처의 한계를 직접 뒷받침하는 근거로는 간접적이다.

참고문헌 [8]과 [10]도 주의가 필요하다. 논문은 두 항목에 같은 제목을 적으면서 [8]에는 다른 저자·연도·쪽수를 배정한다. ACL Anthology의 공식 서지 정보는 해당 제목을 **Ryuichi Takanobu, Hanlin Zhu, Minlie Huang, EMNLP-IJCNLP 2019, 100–110쪽**으로 기록한다. Li·Kiseleva·de Rijke 등이 포함된 2020년 논문의 실제 제목은 [*Guided Dialogue Policy Learning without Adversarial Learning in the Loop*](https://aclanthology.org/2020.findings-emnlp.209/)이고 저자는 8명, 쪽수는 2308–2317이다.

참고문헌 [14]도 제목과 서지 조합을 확인하지 못했다. 논문은 “Sequential deep learning for online conversion prediction with user behavior”를 *Information Processing & Management* 59(1), 102751로 적지만, 출판사 페이지의 [article 102751](https://www.sciencedirect.com/science/article/pii/S0306457321002326)은 Jie Yang 외의 *Social media data analytics for business decision making system to competitive analysis*이다. 이것만으로 인용 대상 연구가 존재하지 않는다고 단정할 수는 없지만, 현재 서지 정보는 일치하지 않으므로 문헌 목록 전체를 원 출처와 다시 대조해야 한다.

## 데이터와 방법

### 논문 v1의 데이터 설명

**저자 보고**에 따르면 데이터는 다음과 같다.

- GPT-4O와 여러 LLM 에이전트로 만든 합성 영업 대화 120만 건 초과
- 15개 산업, 길이·대화 스타일·이의 제기 유형을 프로그램으로 변화
- 대화당 3~27턴, 중앙값 8턴
- 비전환 56%, 전환 44%에 가까운 분포
- 전체 전사, 화자, 최종 이진 결과, 턴별 전환 확률, 모의 참여도, 상품·산업 정보
- 텍스트 정제, 엔터티 표준화, 턴 분할, 특징 추출, 3,072차원 Azure OpenAI 임베딩 생성

논문은 합성 대화의 프롬프트, 생성 모델의 정확한 스냅샷·샘플링 설정, 실패 필터, 중복 제거, 라벨 생성 규칙을 공개하지 않는다. 특히 턴별 “전환 확률”이 어떤 관측 정답인지, 생성 모델이 붙인 주관적 점수인지, 최종 결과에서 역산한 값인지 알 수 없다.

### 상태 표현

논문은 다음 요소를 합쳐 턴 `t`의 상태를 만든다고 설명한다.

1. 최신성과 중요도로 가중한 대화 이력 임베딩
2. 발화 시간, 질문 밀도, 감정 등 턴 특징
3. 응답 시간, 메시지 길이, 질문 여부 등 고객 참여 신호
4. SPIN selling, value selling 등 영업 기법 식별
5. 이의 제기와 관심 신호 탐지

그러나 각 특징의 계산법, 정규화, 누락값 처리, 차원 수와 인코더 구조는 제시되지 않는다. 텍스트 채팅 데이터에서 “발화 시간”과 “응답 시간”이 어떻게 생성·측정됐는지도 불명확하다.

### 모델과 학습

논문의 개념적 구성은 다음과 같다.

```text
대화 접두사
  → 정제·임베딩·영업 특징
  → 상태 인코더
  → 정책 네트워크: 전환 확률
  → 가치 네트워크: 기대 누적 보상
  → 신뢰도 모듈: 유사도·앙상블·새 패턴
  → 확률·신뢰도·전략 안내
```

학습은 초기 지도학습, “신중하게 구성한” 보상의 강화학습, 커리큘럼, 적대적 반례, 앙상블, 균형 배치로 구성됐다고 한다. 강한 정책 정규화, 보수적 업데이트, 난이도별 학습률과 분포 인식 학습도 언급한다. 전체 학습은 표준 CPU에서 약 6시간 걸렸다고 보고한다.

하지만 v1에는 다음 핵심 정보가 없다.

- 사용한 강화학습 알고리즘 이름과 의사코드
- 보상 함수의 수식, 점수 범위와 턴별·종료 보상 결합 방식
- 상태·행동·전이·종료·할인율로 이루어진 MDP 정의
- 정책·가치·인코더의 층, 활성화, 파라미터 수
- 옵티마이저, 학습률, 배치 크기, epoch/timestep, 난수 시드
- 앙상블 개수와 신뢰도 산출·보정식
- 학습/검증/시험 분할과 조기 종료·모델 선택 절차

### 배포 파이프라인

논문은 대화 캡처, 증분 임베딩, 상태 갱신, 확률·신뢰도 예측, 전략 안내, CRM 연동을 설명한다. 8비트 양자화, 반복 요소 캐시, 증분 계산, CPU 최적화, 비동기 안내 생성을 적용했다고 한다. Salesforce·HubSpot, Zoom·Teams·Meet, Outlook·Gmail, Slack·Intercom·Drift 연결기도 언급하지만 공개 문서에는 각 연결기의 구현·인증·보안 검증이 제시되지 않는다.

## 비판적 검토

### 1. 강화학습 정식화가 충분하지 않다

논문은 확률 예측을 “행동”, 정확도를 “보상”으로 둔다. 그러나 예측값이 다음 대화 상태를 바꾸는 메커니즘과 정책이 선택하는 실제 영업 행동을 정의하지 않는다. 지도 라벨에 맞춰 확률을 낮은 손실로 출력하는 문제라면 정책·가치 네트워크라는 이름을 쓰더라도 본질은 순차 지도학습일 수 있다.

후속 모델 카드는 Stable-Baselines3의 PPO와 `[0, 1]` 연속 행동 공간을 명시하지만, 이것은 논문 v1에 없던 정보다. PPO가 사용됐다는 사실만으로 MDP가 타당해지지는 않는다. 환경의 `step`, 다음 상태, 보상, 종료 조건, 과거 행동 정책과 행동의 효과를 공개해야 한다.

### 2. 데이터 분할과 누수 위험이 가장 큰 미확인 항목이다

한 대화에서 만든 여러 턴을 무작위로 서로 다른 split에 넣으면 거의 같은 대화 접두사가 학습과 시험에 동시에 나타난다. 동일 회사·상품·템플릿·생성 seed의 변형이 양쪽에 들어가도 템플릿 누수가 발생한다. 올바른 최소 기준은 **conversation ID 단위 그룹 분할**이며, 더 강한 검증은 회사·산업·템플릿·생성 시점까지 분리해야 한다.

또한 대화의 최종 전환을 암시하는 문구, 턴 수, `probability_trajectory`, 사후에 계산한 참여도나 `sales_effectiveness`가 입력에 들어가면 target leakage가 생긴다. 각 턴에서 실제로 그 시점까지 이용 가능했던 특징만 사용했는지 증명해야 한다.

### 3. 합성 생성기와 평가기가 공유될 수 있다

GPT-4O가 대화, 최종 결과, 확률 궤적과 참여도까지 생성했다면 모델은 실제 영업 법칙보다 생성기의 규칙과 문체를 학습할 수 있다. 같은 생성 분포에서 높은 정확도를 얻어도 실대화 일반화는 보장되지 않는다. 생성 모델·프롬프트·온도·seed를 바꾼 외부 합성 holdout과, 개인정보를 비식별화한 실제 대화 holdout이 필요하다.

### 4. 확률을 주장하지만 보정 평가는 없다

정확도와 AUC는 순위화·임계값 분류를 보여 줄 뿐 0.8이라는 숫자가 실제 80% 전환을 뜻하는지 말해 주지 않는다. Brier 점수, 로그 손실, ECE, 신뢰도 곡선, 턴 위치별 보정, 산업별 보정과 불확실성 구간이 필요하다. 논문은 “confidence intervals”를 제공한다고 서술하지만 그 계산법이나 coverage 평가는 제시하지 않는다.

### 5. 비교 기준의 동등성이 확인되지 않는다

Random Forest와 XGBoost가 같은 3,072차원 임베딩과 영업 특징을 사용했는지, GPT-4 프롬프트가 무엇인지, 상용 시스템이 실제로 전환 예측 기능을 갖는지 알 수 없다. 익명 상용 시스템은 설정을 검증할 수 없다. 범용 생성 모델과 전문 경량 분류기를 서로 다른 입력·출력·비용 조건으로 비교하면 전문 모델이 유리해진다. 모든 기준에 같은 정보와 동일 split을 제공하고 하이퍼파라미터 탐색 예산을 맞춰야 한다.

### 6. 통계적 불확실성과 반복 실험이 없다

정확도와 AUC는 점 추정치 하나만 보고되며, 표본 수와 seed별 평균·표준편차, bootstrap 신뢰구간이 없다. 강화학습은 seed와 환경 확률성에 민감하므로 여러 독립 학습 run이 필수다. 산업·기업·담당자별 성능 분해도 없어 일부 큰 집단이 전체 점수를 끌어올렸는지 알 수 없다.

### 7. 현장 효과의 인과 해석 근거가 부족하다

“무작위 배정”이라는 한 문장 외에 무작위화 단위, 층화, 군별 인원, 순응도, 오염, 중도 이탈, 사전 분석 계획이 없다. 담당자 단위 배정인데 대화를 독립 표본으로 계산하면 군집 상관으로 표준오차를 과소평가할 수 있다. 4개 이상의 지표를 동시에 보면 다중 비교 문제도 생긴다. 기준 전환율이 없으므로 43.2% 상대 증가를 절대 효과나 추가 계약 수로 바꿀 수도 없다.

실시간 안내 사용자가 더 적극적으로 시스템을 쓰는 선택 효과, 담당자 간 전략 공유, 관리자 관심에 따른 Hawthorne 효과, 산업·리드 품질 차이도 통제해야 한다. 원문 자체도 현재 모델이 상관을 찾을 뿐 인과 판별 능력은 제한적이라고 인정한다.

### 8. 지연 시간 비교의 경계가 불명확하다

원격 범용 LLM API의 네트워크 왕복과 생성 시간을 로컬 CPU 예측과 비교한다. 85ms에 대화 캡처, Azure 임베딩 API, 특징 추출, 검색, 신뢰도, 전략 문장 생성까지 포함되는지 명시되지 않는다. 후속 공개물은 LLM 기반 동적 지표도 언급하므로 core PPO 추론과 전체 서비스 지연을 분리해야 한다. 하드웨어, 동시 사용자, 배치 크기, warm/cold cache와 p50/p95/p99가 필요하다.

캐시를 제거했을 때 정확도가 0.017 떨어진다는 제거 결과도 설명이 필요하다. 정확한 캐시는 보통 지연·비용을 바꾸고 모델의 예측값은 바꾸지 않아야 한다. 근사 검색, 만료된 상태, 서로 다른 평가 파이프라인이 섞였다면 정확도 변화 원인을 분리해야 한다.

### 9. 개인정보·공정성·조작 위험이 다뤄지지 않는다

실제 영업 대화에는 이름, 연락처, 회사 기밀, 가격, 재무·건강 등 민감 정보가 포함될 수 있다. 녹음 동의, 목적 제한, 보존 기간, 삭제, 암호화, 접근 통제, 지역 간 데이터 전송과 API 제공자 정책이 필요하다. 확률이 리드 우선순위나 담당자 평가에 쓰이면 언어, 억양, 지역, 회사 규모와 산업에 따른 차별이 확대될 수 있다.

또한 전환 극대화 안내는 고객 복지와 충돌할 수 있다. 압박 판매나 취약 고객 조작을 금지하는 정책, 인간 승인, 거절·이의 제기 존중, 설명·이의 신청과 감사 로그가 필요하다.

### 10. 논문이 인정한 한계

원문은 영어 중심, 텍스트 전용, 담당자별 개인화 부족, 상관과 인과의 차이, 여러 상호작용에 걸친 장기 관계 모델 부족을 한계로 든다. 오디오 특징으로 추가 2~3% 향상이 가능하다는 문장은 예비 실험에 대한 주장일 뿐 실험표나 프로토콜이 없다.

## 후속 공개물과 논문 v1의 차이

2026-09-20에 확인한 저자·기관 연계 공개물은 재현 가능성을 일부 개선하지만, 다음 불일치를 먼저 해결해야 한다.

| 항목 | 논문 v1 | 현재 공개물 | 감사 필요 사항 |
| --- | --- | --- | --- |
| RL 알고리즘 | “특수 강화학습 알고리즘”, 이름 없음 | 모델 카드: Stable-Baselines3 PPO | 공개 체크포인트·학습 코드가 논문 표의 모델인지 commit/hash로 연결 |
| 데이터 규모 | 합성 대화 120만 건 초과 | 모델 카드: 10만 건 이상; 데이터셋 viewer: train 10만 행 | 120만 원자료와 10만 공개 부분집합의 관계, 샘플링·중복 제거 기록 |

| split | 미기재 | 공개 데이터는 단일 train split, 사용자가 직접 분할 | 논문 시험 split ID와 고정 manifest 공개 |
| 성능 근거 | 표 I~III | 모델 카드가 논문 수치를 반복 | 새 공개 가중치에 대한 독립 실행 로그·평가 script 필요 |

공개 데이터셋은 3,088개 열을 가지며 `embedding_0`부터 `embedding_3071`까지 포함하고, 검증·시험 split이 미리 정해져 있지 않다. 이 데이터로 새로 분할해 얻은 결과를 논문 표와 비교하려면 split manifest, 중복 검사와 모델 선택 절차를 고정해야 한다. 모델 카드의 MIT와 데이터 카드의 Apache-2.0은 각각 후속 모델·데이터 라이선스이며, 논문 원문의 CC0와 혼동하면 안 된다.

### 현재 공개 훈련 코드 감사

2026-09-20에 고정 revision `105963aa2bcdaa9a41600366ee7218bb03e397d2`의 [Hugging Face `train.py`](https://huggingface.co/DeepMostInnovations/sales-conversion-model-reinf-learning/blob/105963aa2bcdaa9a41600366ee7218bb03e397d2/train.py)를 읽어 보면, 이 **현재 공개 스크립트**에는 깨끗한 재현 평가로 보기 어려운 표적·미래 정보 노출이 있다.

1. `ConversationState.state_vector`는 `conversation_metrics`의 모든 값을 관측 벡터에 결합한다.
2. `_parse_conversation`은 데이터 행의 정답 `outcome`을 그 metrics 안에 넣는다. 따라서 정책이 예측해야 할 최종 라벨이 상태에 직접 노출된다.
3. `reset`은 `conversion_probabilities`의 첫 값을 정답 `probability_trajectory`의 첫 값으로 초기화한다. 이 값도 상태 벡터에 들어간다.
4. `_get_embedding_for_turn`은 `turn` 인자를 사용해 접두사를 새로 임베딩하지 않고, 한 행에 저장된 전체 대화 임베딩을 모든 턴에서 재사용한다. 전체 대화로 계산한 임베딩이라면 초기 턴 예측에 미래 발화가 노출된다.
5. 보상은 `1 - abs(predicted_prob - true_prob)`로 자동 주석 확률 궤적을 모방하게 하고, 마지막에는 `outcome` 방향으로 추가 보상·벌점을 준다.
6. 분할은 고정 seed 42의 행 인덱스 무작위 분할뿐이며, 기업·템플릿·근접 중복을 그룹으로 격리하지 않는다.

이 구조에서 얻은 높은 점수는 턴별 확률의 독립적인 예측이나 인과 정책 품질보다 **입력에 포함된 라벨 및 자동 생성 궤적의 모방 성능**을 측정할 위험이 크다. 현재 GitHub revision `1c7b97780e6575d4ca3d3cef5f584edacc10a7a3`의 [`predictor.py`](https://github.com/DeepMostInnovations/deepmost/blob/1c7b97780e6575d4ca3d3cef5f584edacc10a7a3/deepmost/core/predictor.py#L191-L192)는 운영 입력에서 `outcome`이 없으면 0.5로 대체한다. 학습 때 실제 결과가 상태에 있었던 모델이라면 이 대체값은 추가적인 학습–추론 분포 차이를 만든다.

중요한 시간 경계도 있다. 공개 `train.py`의 최초 commit은 논문 v1 제출일 뒤인 2025-05-12로 표시된다. 그러므로 이 코드는 **논문 표 I~III가 정확히 이 구현으로 만들어졌음을 증명하지 못한다**. 반대로 현재 공개 패키지를 논문 결과의 누수 없는 재현으로 간주할 수도 없다. 논문 결과와 연결하려면 당시 코드 commit, 데이터 manifest, 모델 파일 hash, split ID와 원시 평가 로그가 필요하다.

## 재현을 위한 최소 프로토콜

### 1. 출처와 버전 고정

- 논문, GitHub commit SHA, Hugging Face model/dataset revision과 파일 SHA-256을 기록한다.
- 생성 모델 배포명, API 버전, 프롬프트, temperature, seed와 생성 날짜를 보존한다.
- 공개 10만 행과 논문 120만 건의 포함 관계를 manifest로 설명한다.

### 2. 누수 없는 분할

- 최소한 `conversation_id` 단위로 train/validation/test를 분리한다.
- company, product, template, customer persona와 생성 seed의 근접 중복을 검사한다.
- 강한 평가에서는 산업·기업·시간을 통째로 holdout한다.
- 모든 턴 특징이 예측 시점 이전에 관측 가능했는지 데이터 계보를 기록한다.
- 확률 궤적·최종 결과·사후 요약이 입력 특징에 섞이지 않도록 차단한다.

### 3. 동일 조건 기준 모델

- 다수 클래스, 로지스틱 회귀, Random Forest, XGBoost, RNN/Transformer 순차 분류기를 포함한다.
- 원문 임베딩만, 임베딩+수작업 특징, 텍스트만을 별도 비교한다.
- 모든 모델에 같은 split·입력 시점·특징과 동등한 탐색 예산을 적용한다.
- PPO가 실제로 필요한지 동일 인코더의 지도학습·밴딧·PPO를 비교한다.

### 4. 확률과 시간축 평가

- 최종 정확도, balanced accuracy, F1, PR-AUC, ROC-AUC를 함께 보고한다.
- 로그 손실, Brier, ECE와 reliability diagram으로 보정을 확인한다.
- 1턴, 25%, 50%, 75%, 마지막 턴 등 대화 진행률별로 성능을 나눈다.
- 산업·언어·채널·고객군과 분포 밖 입력별 오차를 보고한다.
- conversation 단위 bootstrap과 여러 seed 평균·표준편차를 제시한다.

### 5. 불확실성과 선택적 예측

- 신뢰도가 낮을 때 예측을 보류하는 coverage-risk 곡선을 측정한다.
- 임베딩 거리, 앙상블 분산, conformal prediction을 분리 비교한다.
- 낯선 산업·상품·언어를 OOD 세트로 두고 오류 탐지 AUROC와 coverage를 측정한다.

### 6. 공정한 지연·비용 벤치마크

- 같은 하드웨어·지역·요청 길이에서 warm-up 후 반복한다.
- 임베딩, 특징, 검색, core model, 신뢰도, 안내 생성, 네트워크를 단계별 측정한다.
- p50/p95/p99, 처리량, 동시성, 메모리, API 비용과 cache hit/miss를 보고한다.
- 로컬 모델과 API를 비교할 때 업무 결과물과 입력 정보가 같은지 확인한다.

### 7. 사전 등록된 현장 실험

- 담당자 단위 cluster randomization이나 적절한 교차 설계를 사전 등록한다.
- 기준 전환율, 최소 탐지 효과와 power 분석으로 표본 수를 결정한다.
- 주 지표 하나와 보조 지표를 구분하고 다중 비교를 보정한다.
- intention-to-treat를 기본으로 하고 순응도·이탈·오염을 보고한다.
- 담당자 군집을 고려한 신뢰구간과 절대 차이·상대 차이를 함께 공개한다.
- 고객 동의, 안전 중단 규칙, 인간 감독과 불리한 집단별 영향을 감사한다.

## 용어 정리

| 용어 | 뜻 | 이 논문에서의 역할 |
| --- | --- | --- |
| Conversion | 구매·계약 같은 목표 행동 | 최종 이진 결과이자 매 턴 확률 예측 대상 |
| State | 정책이 현재 상황을 표현하는 벡터 | 대화 이력 임베딩과 영업 특징의 결합 |
| Action | 에이전트가 고르는 행동 | 논문에서는 `[0,1]` 전환 확률 출력으로 설명 |
| Reward | 행동의 장기 가치를 학습시키는 신호 | 논문에서는 예측 정확도를 반영한다고만 설명 |
| Policy network | 상태에서 행동 분포를 내는 모델 | 현재 턴 전환 확률 출력 |
| Value network | 상태의 기대 누적 보상을 예측하는 모델 | 구체적 목표·학습법은 미기재 |
| PPO | Proximal Policy Optimization | 후속 모델 카드가 사용 알고리즘으로 명시 |
| Calibration | 예측 확률과 실제 빈도의 일치 | 논문 평가에서 빠진 핵심 품질 |
| AUC-ROC | 임계값 전체의 양·음성 순위 성능 | 표 I의 보조 지표, 보정은 측정하지 않음 |
| Target leakage | 정답 또는 미래 정보가 입력에 섞이는 현상 | 턴·대화 분할과 사후 특징에서 특히 위험 |
| Distribution shift | 학습과 운영 분포의 차이 | 합성→실제, SaaS→타 산업, 영어→타 언어에서 발생 |
| OOD | Out-of-Distribution, 학습 분포 밖 입력 | 신뢰도 모듈이 탐지해야 한다고 주장하는 대상 |
| A/B test | 두 조건을 무작위 비교하는 실험 | 현장 효과의 인과 추정을 위해 필요 |
| Cluster randomization | 집단 단위 무작위 배정 | 담당자별 여러 대화의 상관을 다루는 방법 |

## 실습 학습 가이드

세 노트북은 원 논문의 96.7% 결과를 재현한다고 주장하지 않는다. 외부 API·비공개 데이터 없이 실행하는 **toy reproduction**이며, 주장 검증에 필요한 평가 원리를 익히는 것이 목적이다.

1. [01_foundations.ipynb](01_foundations.ipynb)
   - 합성 턴별 데이터를 만들고 정적·순차 특징을 비교한다.
   - 대화 단위 분할을 적용하고 최종 `outcome`을 입력한 표적 누수가 점수를 어떻게 부풀리는지 확인한다.
   - accuracy와 함께 Brier·log loss·ECE를 측정한다.
2. [02_practice.ipynb](02_practice.ipynb)
   - 수동적인 확률 예측과 실제 행동이 상태 전이를 바꾸는 toy MDP를 분리한다.
   - 예측 품질과 개입 정책의 누적 보상을 구분한다.
   - 순차 예측을 강화학습으로 부를 때 필요한 가정을 점검한다.
3. [03_advanced.ipynb](03_advanced.ipynb)
   - 산업 분포 이동, 앙상블 불확실성, 선택적 예측을 실험한다.
   - 개인 단위 무작위 A/B 실험의 bootstrap 신뢰구간과 표본 크기별 검정력을 살펴본다.
   - 관찰 로그의 교란과 개인정보·공정성·운영 위험을 점검한다.

번역을 먼저 읽으려면 [문장 대조 번역 파일](<SalesRLAgent - A Reinforcement Learning Approach for Real-Time Sales Conversion Prediction and Optimization.번역.md>)로 이동한다.

## 다음 학습 경로

1. **확률 예측**: 로지스틱 회귀, cross-entropy, Brier score와 reliability diagram을 익힌다.
2. **순차 모델**: RNN/Transformer로 대화 접두사별 예측을 만들고 시간축 평가를 수행한다.
3. **강화학습 기초**: MDP, Bellman 식, policy gradient, actor-critic과 PPO를 학습한다.
4. **오프라인 평가**: 행동 정책, importance sampling, doubly robust 추정과 지원 영역 문제를 익힌다.
5. **인과 추론**: 무작위 실험, cluster RCT, uplift modeling과 이질적 처리 효과를 구분한다.
6. **불확실성**: calibration, ensemble, conformal prediction과 selective classification을 연습한다.
7. **책임 있는 배포**: 개인정보 영향평가, 편향 감사, 인간 감독과 모델 모니터링을 설계한다.

이 순서를 마친 뒤에는 공개 DeepMost 코드와 데이터의 정확한 revision을 고정하고, 먼저 누수 없는 지도학습 기준선을 재현한 다음 PPO가 추가 가치를 주는지 검증하는 것이 가장 안전한 후속 과제다.
