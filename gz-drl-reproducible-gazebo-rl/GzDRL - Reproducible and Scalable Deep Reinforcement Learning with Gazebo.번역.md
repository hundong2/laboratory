## 읽기 전 핵심 배경

심층강화학습(DRL, deep reinforcement learning)은 인공신경망 정책이 관측을 받아 행동을 고르고 그 결과 보상을 이용해 갱신하는 접근이다. Gazebo는 물리·센서 시뮬레이션 도구다. 데이터 수집의 한 단위인 전이(transition)를 \((o_t,a_t,r_{t+1},o_{t+1},d_{t+1})\)로 쓰면, 논문의 핵심은 **정책 행동과 다음 상태 기반 관측 사이에 시뮬레이터를 정확히 몇 단계 진행시킬지 제어하는 것**이다. ‘재현 가능’은 모든 난수·플랫폼에서 항상 동일하다는 말이 아니라, 명시한 시드와 설정에서 관측된 재현 실험 결과다.

## Abstract — 한국어 의역

로봇 강화학습은 많은 시뮬레이션 전이가 필요하지만 Gazebo 기반 외부 인터페이스는 통신과 실행 순서 때문에 행동을 적용한 시점과 상태를 읽는 시점이 흔들릴 수 있다. 저자들은 Gazebo 내부에서 행동·물리 스텝·관측을 동기화하고, 여러 서버를 병렬 실행하며, 벡터화 학습기에 데이터를 전달하는 GzDRL을 제안한다. 저자들이 수행한 UAV 제어 과제에서는 동일 시드의 PPO 실행이 일치했고, 특정 워크스테이션 헤드리스 벤치마크에서 높은 처리량을 보였으며, 학습한 정책의 제한된 실기체 전이를 제시한다. 수치는 장비·환경 수·과제별로 달라진다.

## I. Introduction — 문제 제기

현실의 로봇에서 위험하거나 시간이 드는 탐색을 대신하려고 물리 시뮬레이터로 정책을 훈련한다. 로봇 모델·센서가 풍부한 Gazebo를 사용하더라도, 강화학습의 `step()`이 실제 물리 시간과 일대일로 대응하지 않으면 비교 가능한 학습 데이터를 만들기 어렵다. 저자의 목표는 동기화된 상태 전이, 빠른 다중 환경 자료 수집, 같은 조건의 반복 실험을 하나의 프레임워크에 결합하는 것이다. 시뮬레이션에서 실기체로 정책을 옮기는 실험도 소개하지만 이는 프레임워크의 모든 환경에 대한 일반화 보장이 아니다.

## II. Related Work — 선행 연구의 위치

저자들은 Gazebo를 ROS 2 인터페이스와 결합하는 방식, Gazebo 내 확장 및 GPU 병렬 시뮬레이션 계열을 비교 대상으로 둔다. 논문의 주된 설계 차이는 외부 통신의 비동기 지연에 의존하지 않고 시뮬레이터의 물리 스텝을 학습 환경의 호출 안에서 실행하는 것이다. GPU 기반 Aerial Gym은 다른 성능 특성이 있으므로, 헤드리스 CPU 중심 설정의 일부 승리를 모든 플랫폼의 우위로 해석하지 않아야 한다. 선행 연구의 전체 서지는 [원문 References](https://arxiv.org/html/2609.13243v1)에서 확인한다.

## III. GzDRL Platform — 상태와 제어

### A. UAV 상태 및 액추에이터

논문은 위치 \(p_W\in\mathbb{R}^3\), 속도 \(v_W\in\mathbb{R}^3\), 자세를 나타내는 단위 사원수 \(q\in\mathbb{R}^4\), 기체 좌표계 각속도 \(\omega_B\in\mathbb{R}^3\)를 묶어 13차원 상태로 정의한다:

\[
x = \operatorname{col}(p_W, v_W, q, \omega_B) \in \mathbb{R}^{13}.
\]

이는 ‘변수 열을 순서대로 쌓는다’는 표기다. 원문의 **식 (1)은 이 정의 자체가 아니라 다음 13차원 운동방정식**이다.

\[
\dot{x}=f(x,u)=\begin{bmatrix}
v_W\\
\frac{1}{m}(R T_B+F_W)+g_W\\
\frac{1}{2}q\otimes(0,\omega_B)\\
J^{-1}(\tau_B+M_B-\omega_B\times J\omega_B)
\end{bmatrix}.
\]

\(m\)은 질량, \(J\)는 대각 관성 행렬, \(R\)은 자세에 따른 회전행렬, \(T_B=\operatorname{col}(0,0,T)\)는 기체 좌표계 총추력, \(F_W\)와 \(M_B\)는 외란 힘·모멘트, \(g_W\)는 중력, \(\tau_B\)는 제어 토크다. 입력 \(u=\operatorname{col}(T,\tau_B)\)로부터 속도·가속도·사원수 변화·각가속도를 구한다. \(W\)는 월드, \(B\)는 기체 좌표계다. 학습자가 반드시 13개 출력 행동을 만드는 뜻은 아니며 관측 상태와 행동 차원을 구별해야 한다.

식 (2)의 1차 액추에이터 모형은 한 물리 간격 \(\Delta t\)에서

\[
u(t+\Delta t) = u(t)e^{-\Delta t/t_c} + u_{\mathrm{ref}}(t)(1-e^{-\Delta t/t_c})
\]

로 설명할 수 있다. \(u(t)\)는 현재 실제 입력, \(u_{\mathrm{ref}}(t)\)는 목표 명령, \(t_c>0\)는 시정수다. 출력은 단순히 목표 명령으로 즉시 바뀌지 않는다. \(t_c\)가 크면 추종이 느려지고, \(\Delta t\)가 작으면 한 번의 갱신 변화가 작다. RPM, SRT, CTBT, CTBR, wrench, 운동학적 명령, guidance 등 논문이 나열한 여러 제어 모드는 물리 상세도와 정책 출력의 의미가 다르다.

### 플랫폼 구성 개요

저자의 구성은 Gazebo 안의 로봇·제어·상태 갱신과 바깥의 학습기 인터페이스를 잇는다. 상태가 언제 기록되는지, 명령이 어느 물리 스텝에 적용되는지를 제어해야 지연이나 중간 전이를 모호하게 섞지 않는다. 같은 시드를 준 것만으로 결정론이 자동 보장되지는 않으므로 자원 배치·모델·물리 설정도 기록해야 한다.

## IV. Execution Architecture — 전이와 병렬화

### A. 식 (3): 동기식 `step`

논문 식 (3)의 뜻을 실행 순서로 풀면 다음과 같다.

1. 환경 \(i\)가 정책 행동을 한 번 처리한다.
2. \(k=1,\ldots,K\)마다 최신 상태를 읽고 제어기를 갱신한 후 `gz::sim::Server::Run(1)`로 물리 스텝 **정확히 한 번**을 실행한다.
3. `PostUpdate` 뒤의 상태를 모아 관측, 보상, 종료 여부를 계산해 반환한다.

이 ‘정확히 정해진 물리 스텝’ 성질은 논문의 설명대로 **상태 관측(state observations)**에 적용한다. 카메라 등 렌더링 관측은 Gazebo 렌더링 파이프라인에 따라 별도로 검증해야 한다. 궤적 추적 정책 학습의 \(K=10\), \(\Delta t=0.001\,s\) 설정이면 행동 간격은 \(0.01\,s\), 명목 제어 주파수는 100 Hz다.

### B. 두 가지 병렬 인터페이스와 Algorithm 1

`AsyncDRLServerPool`은 각 서버의 전용 작업자로 여러 Gazebo 서버를 진행시키고 Python GIL(전역 인터프리터 잠금)을 해제하는 C++ 작업 경로를 이용한다. `GazeboPool`은 EnvPool 계열의 동적 작업 대기열을 활용하고, \(N_E\)개 환경에 \(N_T\)개 작업자를 할당해 \(N_B\le N_E\)개 완료만 기다린 뒤 부분 배치를 반환할 수 있다. 논문의 Algorithm 1은 ‘작업 제출 → 완료 환경 식별 → 결과 수집 → 다음 행동 제출’의 반복을 서술한다.

NumPy 배열은 C++ 소유 버퍼를 **복사하지 않는 view**로 참조한다. 다음 배치에서 메모리가 재사용될 수 있으므로 결과를 오래 보관해야 할 때는 별도 복사가 필요하다. 환경 하나에 여러 상호작용 에이전트가 있어도 이들을 항상 서로 독립인 \(N_E\)개 환경으로 셀 수는 없다.

## V. Experiments — 실험 결과와 해석

### A. 동기화 실험

같은 과제·초기 상태로 100회 수행하여 행동→물리 지연, 관측 지연, 중간에 개입한 물리 스텝을 측정했다. 비교한 ROS 2–Gazebo 구성보다 GzDRL의 상태 궤적이 더 일치했다. 특정 통합 구성과 부하에서 나온 차이를 ROS 2 자체의 보편적 한계로 일반화할 수는 없다.

### B. 재현성 실험 — Table II

Hover PPO 학습을 동일 seed 다섯 번과 서로 다른 seed `{1,5,25,42,125}`로 다섯 번 수행한다. 환경은 8개, 실행당 500,000 스텝, 체크포인트 간격은 50,000 스텝이다. 별도 평가 프로세스에서 20개 고정 seed 에피소드와 고정된 정규화 통계를 이용한다. 논문의 동일-seed 결과는 최종 return `18.43 ± 0.00`, 변동계수 0%, 체크포인트 해시 일치 100%; 다른-seed 결과는 `18.08 ± 1.27`, 변동계수 7.05%, 해시 일치 0%다. 이 수치의 단위와 조건을 바꾸어 재현성을 주장해서는 안 된다.

### C–D. 처리량과 다중 에이전트 — Tables III–IV

헤드리스 hover 성능 실험은 물리 간격 1 ms, 환경 수 `{1,4,8,16,32,64,128}`, 조건당 5회, 1,000 스텝 준비 운전과 10,000 스텝 계측을 사용한다. 워크스테이션(AMD Threadripper 3960X, RAM 256 GB, A6000 두 장)에서 GzDRL GazeboPool은 환경 128개의 최고 `78.58 ± 2.08 × 10³` 환경 전이/s를 기록했다. 노트북(Ryzen 9 7940HS, RAM 32 GB, RTX 4060)에서는 GzDRL 환경 32개에서 `43.38 ± 0.56 × 10³`, Aerial Gym 환경 128개에서 `44.56 ± 0.42 × 10³`으로 비교 대상이 더 높았다. 다른 환경 개수의 정점끼리 비교한다는 점도 함께 읽어야 한다.

환경 32개에서 환경당 에이전트를 2, 5, 10, 20개로 늘린 실험에서는 워크스테이션 GzDRL의 전이/s가 각각 `35.52`, `17.82`, `8.10`, `3.18`천으로 줄었다. 같은 조건의 Aerial Gym은 `7.15`, `7.07`, `6.62`, `5.53`천이다. 에이전트 20개에서는 Aerial Gym이 앞선다. 노트북에서는 에이전트 5개부터 Aerial Gym이 앞선다. 이는 환경 수를 늘리는 것과 환경 *내부* 상호작용 에이전트를 늘리는 것이 다른 비용임을 보여준다.

### E. 정책 학습의 규모

두 제어 모드의 궤적 추적·페이로드 운반 과제에서 Stable-Baselines3 PPO, `[512, 512]` 다층퍼셉트론, seed 세 개 `{1,25,42}`, 구성별 15개 환경, 500만 전이를 사용한다. 궤적 추적에는 1 kHz 물리·100 Hz 제어가 명시되고, 페이로드 운반에는 1 kHz 물리 주파수가 명시된다. 논문은 각 과제의 동시 학습 구성에서 90개 병렬 환경과 약 220분 경과시간을 보고한다. 정확한 성능 비교에는 보상 정의·초깃값·정규화·하드웨어와 학습 시드의 동일화가 필요하다.

### F. 도메인 무작위화

역진자 과제에서 질량, 관성, 액추에이터 시정수를 기준의 0.9–1.1배 범위에서 10 에피소드마다 무작위화한다. 1,000개 무작위 조건 평가에서 고정조건 학습 정책의 return은 `439.89 ± 175.97`, 무작위화 학습 정책은 `642.97 ± 232.07`이었다. 반대로 학습 중 보고값은 각각 `427.98 ± 138.62`, `398.45 ± 130.33`이다. 학습 보상과 시험 보상, 두 정책의 평가 분포를 혼동하지 않는다.

### G. 실기체 전이 — Table V와 짧은 문장 대조

별도 미세조정 없이 고정한 정책을 QDrone2의 아홉 가지 시드 궤적에 적용했다. Jetson Xavier NX의 **정책 추론 100 Hz**, OptiTrack의 120 Hz 외부 위치 피드백과 별도 내부 제어기가 있는 설정이다. 이륙·종료 구간을 제외한 움직이는 참조 궤적에서 평균 유클리드 오차는 `20.2 ± 3.4 cm`, 3D RMS는 `26.2 ± 7.4 cm`(논문의 95% 신뢰구간 표기)였다.

- **용어·약어 해설:** 액추에이터 포화(actuator saturation)는 모터·제어기가 낼 수 있는 최대·최소 출력에 명령이 걸리는 상황이다. 이 문장은 위 아홉 번의 실험에서 **관측되지 않았다는 보고**이지 다른 비행 조건에서 안전을 보장한다는 뜻이 아니다.

## VI. Conclusion — 결론의 한국어 의역

저자들은 Gazebo의 물리 실행을 학습 환경 호출에 묶어 재현 가능한 상태 기반 전이와 병렬 수집을 구성했다고 결론짓는다. 정책 훈련과 실기체 궤적 추적의 예를 제시하며 Gazebo 기반 로봇 DRL 실험을 위한 기반으로 본다. 해설: 이미지 관측, 다른 물리·센서 조합, 더 큰 에이전트 군집, 외부 위치 추정이 없는 실기체에서의 재현·효율은 별도 실험이 필요하다. 이 마지막 문장은 저자 주장의 직접 인용이 아니라 본문 평가 범위에서 도출한 학습자용 주의사항이다.
